# OpsOne 模块路线图

OpsOne 的目标是把主机与资产、运维执行、容器、监控告警、安全合规、组织权限收敛到一个工作台里，面向中小规模自建环境。本文件是模块清单与实现状态的单一来源。

菜单与权限位已全部就位（`server/internal/db/db.go` 的 `Seed`），未实现的模块指向 `/placeholder/index` 占位页。菜单 ID 按模块分段，新增子项在本段内追加即可。

状态说明：`[x]` 已实现可用 · `[~]` 部分实现 · `[ ]` 仅有菜单占位


## 工作台（ID 10-19）

- [x] 平台总览 `/dashboard/overview` — 主机总数/在线离线、环境分布、最近执行
- [x] 个人工作台 `/dashboard/personal` — 待办（未读消息、未恢复告警）、我的主机与定时任务、我最近的执行与会话
- [x] 我的资源 `/dashboard/my-resources` — 按数据范围过滤的主机统计、环境与部门分布、在线率、离线优先列表
- [x] 我的活动 `/dashboard/my-activity` — 我的操作流水、我的终端会话、我发起的批量执行


## 资产管理（ID 100-199）

- [x] 主机资产 `/asset/host` — CRUD、环境/标签/状态过滤、连通性探测、跳板机关联、CSV 批量导入导出（模板下载、试运行报告、按 address+port 幂等更新，**导出不含登录凭据**）
- [x] 数据库资产 `/asset/database` — 实例纳管（MySQL/PG/Redis/Mongo）、按类型带默认端口；连通性检查对 MySQL/PG **真建连接**并回写版本号，其余类型退化为 TCP 端口探测
- [x] 云账号 `/asset/cloud` — 云账号与密钥台账（AK 列表页脱敏展示）；**不做资源同步**，需各厂商 SDK 与出网能力

- [x] 标签管理 `/asset/tag` — 标签字典、分类与配色、主机/数据库用量统计，表单内可选可新建
- [x] 固定资产 `/asset/fixed` — 设备台账、SN/型号/位置/使用人、关联主机、采购与保修、到保提醒与原值合计

- [x] 资产盘点 `/asset/inventory` — 批次快照、逐条登记（正常/缺失/位置变更）、完成时未盘按缺失处理、进度与结果统计
- [x] 采购记录 `/asset/purchase` — 单据 + 明细、金额自动汇总、收货入库可按明细生成固定资产


## 运维执行（ID 200-299）

- [x] 导航与可发现性 — 侧边栏递归渲染（支持三级及更深），「运维执行 → 堡垒机」把 Web 终端 / 会话审计 / 文件管理收成一组（这三件事合起来才是大家认知里的堡垒机，散在一级列表里会让人以为平台没这个能力）；顶栏菜单搜索（Ctrl+K，按标题跳转并显示所属分组）；占位页明确写「功能尚未实现」并给出路线图位置与当前可替代的能力。**内置菜单的标题/图标/排序仍由管理员在菜单管理里维护，代码升级不覆盖**
- [x] Web 终端 `/execute/terminal` — SSH PTY、窗口自适应、跳板机隧道、会话录像、命令拦截

- [x] 批量执行 `/execute/batch` — 并发下发（上限 10）、单机超时、生产二次确认（后端强制，不是只有前端弹窗）、下发前预检、执行历史
- [x] 会话审计 `/execute/session` — 会话流水（操作人/登录账号/主机/状态/风险/时间范围筛选）、跨会话命令检索（关键字 + 风险 + 操作人 + 主机 + 时间范围，命中即可跳到录像对应时间点）、会话内命令明细分页、命中规则描述快照、按条件导出 CSV、录像回放（倍速 + 命令定位）；**不做击键级录制、不对录像做 OCR/全文检索，检索也不按数据范围过滤**（能进这个菜单就能看到所有人的命令）
- [x] 文件管理 `/execute/file` — SFTP 目录浏览、上传、下载、新建目录、重命名、删除空目录，动作全留痕（含连接失败的尝试）
- [x] 定时任务 `/execute/scheduler` — 标准五段 cron、多主机并发下发、启停与立即执行、运行记录复用批量执行历史
- [x] 脚本库 `/execute/script` — 分类/说明/参数化（`${PARAM}` + 必填 + 默认值）、命令规则静态预检（拦截级禁止下发）、渲染预览、下发复用批量执行链路、使用计数；**不做版本管理与审批流**
- [x] 构建发布 `/execute/build` — Jenkins 服务器登记与连通性测试、参数化触发构建、构建记录手动同步状态（平台不轮询）
- [x] 下发闸门 — 所有命令下发路径（批量执行/脚本/定时任务）在 `RunOnHosts` 处统一拦截：命令规则逐行匹配（拦截级不下发）+ 生产主机显式确认（后端强制）；定时任务保存时就校验命令与生产确认；被拦下的下发不产生执行记录，独立记入拦截流水（`exec_guard_logs`）；补了定时任务编辑与立即执行的两处数据范围缺口。**不做审批、双人复核、变更窗口与限流**

- [x] 数据库查询 `/execute/db-query` — 复用「数据库资产」里的实例（MySQL/PG）浏览库/表/字段/索引（含注释、行数估算、视图标记）并执行**只读 SQL**；三层防线 = 语句白名单（只放 select/with/show/explain/describe，拒多语句、注释绕过、`INTO OUTFILE`/`FOR UPDATE`/`pg_read_file`/`COPY ... TO PROGRAM`/`sleep`/`benchmark`）+ 会话级只读（PG `default_transaction_read_only`、MySQL `SET SESSION TRANSACTION READ ONLY`）+ 库侧只读授权；500 行截断并标注、30s 语句超时、CSV 导出（BOM，≤10000 行）、执行前预检、全量查询流水（语句原文/操作人/来源 IP/耗时/行数/拦截原因，留存天数可配）。**不做写操作、结果集编辑、Redis/Mongo、BI 报表与 AI 生成 SQL**


## 容器平台（ID 300-399）

- [x] 集群接入 `/kubernetes/source` — 粘贴 kubeconfig 纳管（解析上下文后选用哪个）、连通性与版本检查、节点就绪明细（角色/容量/kubelet/cordon）；不可达或有节点 NotReady 自动写告警并可恢复，定时检查由 `OPS_KUBE_CHECK_SPEC` 控制。**只接受内嵌凭据**，不支持路径式 kubeconfig；**kubeconfig 明文存库**，见 docs/SECURITY.md 第 16 节
- [x] 工作负载 `/kubernetes/workload` — 按命名空间看 Deployment / StatefulSet / DaemonSet 的副本就绪情况、Pod 状态与容器异常原因、集群事件（可只看 Warning）；Pod 行可直接看**容器日志**（多容器/init 容器切换、行数 200~5000、时间戳、上一个容器、每 5 秒自动刷新、下载，单次 1MB 上限并标注截断）。**不做 follow 流式跟随**、**不提供 exec**；资源改动走「资源管理」
- [x] 资源管理 `/kubernetes/resource` — 按类型列资源（带类型相关摘要）、看单个对象的可编辑 YAML（自动清掉 status 与 resourceVersion / uid / managedFields 等集群自维护字段）、服务端 apply（`fieldManager=opsone`）并可先 `dryRun=All` 预检、Deployment / StatefulSet 直接改副本数（`/scale`，同样可预检）；字段冲突返回 409 并带出冲突字段，可显式「强制接管」；每次改动（含预检与失败）写 `kube_change_logs` 留痕，记录提交的 YAML 原文与 API Server 原话，写操作绑 `kube:write`。**类型白名单**（Deployment / StatefulSet / DaemonSet / CronJob / Service / ConfigMap / Ingress），**不提供删除**，**不开放 Secret / Namespace / RBAC**，**一次只提交一个对象**（多段 YAML 拒绝），也**不做版本回滚与 diff**
- [x] 服务转发 `/kubernetes/forward` — 把 Pod / Service 端口映射到平台上的一个 TCP 端口（相当于把 `kubectl port-forward` 挪到平台跑）；走 API Server 的 **WebSocket** 通道（不引 client-go，也不自己实现 SPDY），每条本地连接单开一条 WebSocket；Service 目标每条连接重新解析后端 Pod，Pod 重建/扩缩容后隧道仍可用；实时展示活跃与累计连接、双向流量、剩余时长、拨号失败原因，到期自动关闭并把计数写回档案。约束由环境变量定死（监听地址、端口区间、隧道数、单隧道并发、TTL）。**隧道是进程内的活物，重启即消失**（启动时把残留记录标为已关闭）；**隧道端口不做认证**，见 docs/SECURITY.md 第 16 节；**不做 UDP 转发、不做多端口一条隧道、不做长连接复用（每条连接一条 WebSocket）**

> 实现方式：手写 Kubernetes REST 客户端（`server/internal/k8s`），不引入 client-go —— 只读列表与服务端 apply / scale 都是普通 HTTP 请求（`application/apply-patch+yaml`、`application/merge-patch+json`），不值得为此背上几十兆依赖树。port-forward 也没走 SPDY：kubelet 还支持一套朴素的 WebSocket 通道协议（通道号 + 2 字节端口号前缀），各语言客户端库用的就是它，已在 k3s v1.31 上实测打通。

## 监控告警（ID 400-499）

- [x] 告警态势 `/monitor/situation` — 趋势折线（24h/7d/30d 分桶）、级别与来源分布、Top 标签、平均确认与恢复时长

- [x] 告警列表 `/monitor/alerts` — 概览卡片、级别/状态/关键字筛选、确认与恢复、投递流水
- [x] 告警规则 `/monitor/alert-rules` — 11 个内置指标（全部取平台自身数据，不依赖 Prometheus）、比较符 + 阈值 + 统计窗口 + 连续命中降噪、定时评估与手动试跑、命中写告警并自动恢复；**不含 PromQL 与外部指标源**
- [x] 检测规则 `/monitor/detection-rules` — 多告警关联：并发窗 / 顺序链 / 窗口 Join（按标签对齐到同一对象），每步按标题摘要关键字 + 接入源 + 级别 + 标签匹配；窗口内发生过的告警都算（含已恢复），命中写告警并自动恢复，草稿可「预演」看每步命中明细；排除自身产生的告警以防自激。**不做跨平台事件流接入**，只关联本平台告警表
- [x] 通知路由 `/monitor/routing` — 优先级 + 级别/标签匹配、兜底路由、选路预演

- [x] 聚合策略 `/monitor/aggregation` — 按接入源/级别/标题/任意标签维度实时归桶、成桶阈值、归桶预览、策略重叠检测；可选「抑制通知」（同桶窗口内只通知首条，其余仍入库并在告警上记录抑制来源）
- [x] 静默与维护窗口 `/monitor/silences` — 时间窗（右开区间、单条最长 30 天）+ 匹配条件（级别 / 来源 / 标题关键字 / 标签，填了的都要命中；不填必须显式勾选「匹配全部告警」）；**只拦外发通知、不拦入库**，被拦的告警记 `silenced_by` / `silence_id`（与聚合的 `suppressed_by` 分开存，否则会把被静默的告警当成「已通知过的首条」而破坏聚合语义）；保存前可试算命中范围；支持提前结束、停用、命中计数与命中告警列表；**值班升级按当下时间重新判定**，窗口里不叫人、窗口一过自动恢复；已拦过告警的窗口禁止删除。**不做周期性静默**（每周三 2:00 这类），一次性窗口 + 提前结束够用；也不按主机/服务对象静默——用标签条件表达
- [x] 事件中心 `/monitor/events` — 从告警或聚合桶升格为事件、指派负责人（附站内消息）、处置时间线、状态流转（待处理/处理中/已解决/已关闭）、解决时可联动恢复关联告警、诊断上下文（按标签反查主机/拨测/证书/规则的当前状态）；**平台不自动建单**
- [x] 指标查询 `/monitor/metrics` — 接入已有 Prometheus（兼容实现同理）：多数据源 + 默认源、连通性检查（buildinfo + tsdb 状态，展示版本与序列数）、即时查询（表格）与范围查询（折线图，步长按范围自动算、点数上限对齐 Prometheus 的 11000）、指标名补全、常用查询收藏。PromQL 错误与警告原样透出（带 errorType）。**平台不存时序数据**、**不改写 PromQL**、**不做告警规则联动**（那是 Prometheus / Alertmanager 或平台自己的「告警规则」的事）、曲线超 60 条截断
- [x] 日志查询 `/monitor/logs` — 接入已有 Loki：多数据源 + 默认源 + 多租户（`X-Scope-OrgID`）+ 鉴权头、连通性检查（用 labels 接口，顺带报最近一小时标签数）、LogQL 查询（时间范围、条数上限 5000、最新/最旧在前）、标签与标签值下拉直接拼出 `{k="v"}` 选择器、跨流按时间归并成一条时间线、单行超 8000 字符截断并标记、结果可下载、显示 Loki 扫描的行数与字节数。Loki 的报错常是纯文本（不像 Prometheus 有 JSON 信封），已按这一点处理并原样透出；聚合类表达式返回 matrix 时明确提示去「指标查询」页。**不做实时 tail**（要长连接；真要盯日志更适合 `kubectl logs -f` 或 Grafana）、**不做日志落库**、**不做标签级细粒度授权**
- [x] 链路追踪 `/monitor/traces` — 接入已有 Jaeger（Query API）：多数据源 + 默认源 + 鉴权头、连通性检查（服务列表，顺带报服务数）、按服务/操作/最小耗时/时间范围/标签搜 trace、列表给出入口服务与操作、总跨度、span 数、涉及服务与出错 span 数（可只看有错的）、按 TraceID 直查；详情是 span 瀑布图（深度优先排列 + 相对偏移，点 span 看全部标签），span 超 800 个截断并告知。出错判定同时认 `error=true`、HTTP 5xx、`otel.status_code=ERROR`。Jaeger 的错误体**有时带着 HTTP 200**，已按这一点处理。**不接收上报、不存链路数据**、**不做服务依赖拓扑图**（Jaeger 自带）、**不做 Tempo/Zipkin 适配**（可后续按同一套 source 模型扩）
- [x] 拨测探测 `/monitor/probe` — HTTP（状态码 + 响应体关键字）与 TCP 拨测、连续失败降噪、失败写告警并自动恢复、历史记录保留天数由「数据留存」统一配置（默认 7 天）、可用率统计；**所有拨测共用一个执行节奏**，不支持每条独立周期
- [x] 业务拓扑 `/monitor/topology` — 节点绑定平台已有资源（主机/数据库/拨测/证书）或标为外部依赖，健康度实时换算自被绑资源的当前状态并给出判定理由；SVG 画布可拖动、布局批量保存；连线校验（禁自环、禁重复、两端必须同属一张拓扑）、依赖成环只提示不拦。**不做自动发现与自动布局**，也**不产生告警**：状态是即时读的，告警归「告警规则」
- [x] 平台健康 `/monitor/health` — 运行时、定时调度（含内置固定任务最近运行）、告警链路（渠道/兜底路由/投递失败/规则状态/积压）、资产探测覆盖、数据库与录像占用；即时计算，**不做历史趋势**
- [x] 主机指标 `/monitor/host-metrics` — 走 SSH 采集 CPU/内存/磁盘/负载/进程/连接/运行时长，**不装 agent、不依赖 Prometheus**；远端只读原始数字、换算在平台侧（可单测），磁盘只统计真实块设备（排除 snap squashfs 与只读镜像挂载，否则 100% 恒满会天天误报）；采集失败落库并可告警，过期样本不参与告警判定，趋势图按 1/6/24 小时与 7 天查看。**不做秒级采样**：节奏就是 `OPS_HOST_METRIC_SPEC`（默认 5 分钟）；**不统计网络挂载**（NFS 等）
- [x] 值班升级 `/monitor/oncall` — 排班表按小时/天/周轮换（交接时刻取基准时间的时分）、可按级别只接管部分告警、代班时间段顶替当班人；firing 且未确认超时逐级升级（每级叫对应位次成员），站内消息必发 + 可选邮件，每次叫人落一条升级记录（缺邮箱记失败而非静默跳过）；同告警同级去重、只扫最近 24h 且不早于排班表创建时间的告警；可试跑。**不支持短信/电话**（`User` 没有手机号字段），**不做换班审批**，通知也不另起渠道体系——复用站内消息与已有 SMTP
- [x] 公网监测 `/monitor/public-ip` — 登记每台对外机器该开哪些端口（`22,80,443,8000-8010` 混写，单目标上限 1024 个端口），平台从自身网络位置定时做 TCP 连接核对：开着但没登记的端口写告警并可自动恢复，可一键把当前开放端口「登记为基线」；也记录「登记了却没开」但不为此告警（避免和拨测重复）；基线里没扫到的端口不做判断；每次扫描落历史，保留天数进「数据留存」。**只做 connect 探测**：不发探针载荷、不识别服务指纹、不做全端口扫描、不扫 UDP；**不自动发现资产**（目标靠登记），也**不查平台自己的出口公网 IP**（那要依赖外部 echo 服务）

## 安全合规（ID 500-599）

- [x] 证书管理 `/security/ssl` — TLS 探测（颁发者/SAN/有效期/指纹/链校验）、按证书设置到期阈值、定时巡检、到期与失败自动写入告警并可恢复；**不含自动续签（ACME）**
- [ ] 防火墙策略 `/security/firewall` — 边缘规则下发与审计
- [x] 双因子口令 `/security/twofa` — 平台账号绑定标准 TOTP（扫码/手动录入）、登录两步校验、验证码防重放、强制模式后端真拦截、管理员重置；**不含恢复码**，也**不是主机登录口令的 TOTP 金库**
- [ ] 安全意识 `/security/awareness` — 培训与考核

## 智能与成本（ID 600-699）

## 已落地：防火墙策略 `/security/firewall`

原先是占位页，现已实现「SSH 读真机 + 平台登记 + 对账 + 预检 + 下发 + 快照回滚」。
两个设计决定值得记下来：

- **不做平台镜像**：真机规则每次现读（`internal/fwx`），平台只存期望状态与运维元数据
  （责任人 / 生命周期 / 到期时间）。防火墙规则谁都能上机器手改，镜像一定会过期，
  只落库不对账的功能等于骗人
- **不装 agent**：因此实时流量监控、进程连接、带宽限速、Agent 接入审批这四项明确不做
  （参考站那四页是 agent 方案）。纯 SSH 只能定时采样，做一个「看起来实时」的页面比不做更糟

下一步如果要继续加深：Kubernetes 按集群下钻（参考站有约 30 个资源页 + 按集群 RBAC 授权）。

## 已落地：凭证库 `/security/credential`

主机凭据原先内嵌在主机记录里，换一次口令要逐台改、改漏的那台静默失效。现在共享凭据独立成表，
主机通过 `hosts.credential_id` 引用，解析点收在 `buildTarget` 一处，六条 SSH 链路（终端 / 批量执行 /
文件 / 采集 / 防火墙 / 探测）自动跟着生效，跳板链也天然继承。

三个设计决定：

- **加密是可选的，但必须说实话**：配了 `OPS_SECRET_KEY` 才是 AES-GCM 密文（`internal/cryptox`），
  没配就是明文，页面顶部照实标注。历史明文记录不自动重写，轮换一次才转密文 ——
  偷偷改写存量数据，出问题时没人解释得清楚
- **绝不静默回退**：凭据被禁用 / 删除 / 解不开密时，引用它的主机连不上并点名原因
  （`sshx.Target.PrepareError`）。回退到主机自带的旧口令看起来更可用，实际是把
  「我以为已经换掉了」变成安全事故
- **顺序是先测再铺**：测试连接用目标主机的地址与跳板链、认证强制用被测凭据，绑定前就能验；
  轮换后不自动逐台复验（几十台串行要几分钟），而是明确告诉人「影响 N 台，挑一台点测试连接」

顺带补上了一个一直缺的能力：**带口令的私钥**。此前用的是 `ssh.ParsePrivateKey`，加密私钥直接报错，
等于平台完全不支持这类钥匙。

下一步：其它类型的密钥（kubeconfig、数据库实例、云账号、Jenkins Token、模型上游 Key）目前仍各自
明文存在自己的模块里，可以逐步收进凭证库；再往后是 SSH CA 签发短期证书的「凭据不落地」方案。

## 已落地：Kubernetes 按集群下钻（资源管理页扩容）

参考站按集群铺了约 30 个资源页，这里没照抄页面数量，而是把**一页能下钻**做通：
资源类型从 7 种扩到 17 种（按工作负载 / 网络 / 配置 / 存储 / 集群分组），对象详情除 YAML 外
增加「它自己的事件」与「关联 Pod」两个页签，工作负载增加滚动重启。

几个决定：

- **类型分三档而不是一刀切**：可写 / 只读 / 脱敏只读。Pod、ReplicaSet、Node 这些由控制器维护的
  对象给只读（编辑入口干脆不给，而不是点了再报错）；Secret 给「脱敏只读」——
  「这个 Secret 里有没有 tls.key 这个键」是真实需求，值本身谁都不需要在平台上看。
  脱敏过的 YAML 必须禁止提交，否则会把真实值覆盖成占位符，那比不做这个功能糟糕得多
- **RBAC 连只读都不开**：能看到全部权限绑定本身就是侦察面
- **关联关系只认集群自己的选法**：按 `spec.selector` 的等值标签查 Pod，`matchExpressions`
  问不出来时返回空并说明原因，不按名字前缀猜 —— 猜出来的关联比没有更危险
- **滚动重启说清它是什么**：给 Pod 模板打 `kubectl.kubernetes.io/restartedAt`（与 kubectl 同一个注解键，
  两边看到的是同一回事），界面明说这不是原地重启容器、副本为 1 时会有短暂不可用

真集群验证（WSL 里的 k3s v1.31.5，41 项断言全过）里最关键的一条：重启之后不只看接口返回，
而是等控制器把 Pod 换掉、确认旧 Pod 名字已经消失 —— 否则「重启成功」就只是一句话。

下一步如果继续加深容器平台：Pod 的 exec（需要先想清楚审计怎么做，
不能像终端那样只录 SSH）、以及告警与容量的联动。

## 已落地：密钥落库加密推广 + 加密体检

凭证库那一轮只加密了 `credentials` 表，而权限最大的两份凭据其实在别处：
`kube_clusters.kubeconfig`（通常等同 cluster-admin）和 `hosts.secret`。这一轮把它们
和 `db_instances.secret` 一起纳入同一套 AES-GCM。

两个决定：

- **不用 GORM 钩子，在读写点显式调用**。钩子看起来更保险（"没有一条写路径能绕过"），
  但它在 `Save` 全列写回、`Updates(map)`、`Select(...).Updates(struct)` 这几种形态下行为差别很大，
  一处理解错就会把密文再加密一次或把明文写回去 —— 这种 bug 在库里是不可逆的。
  显式调用的代价是「可能漏一条写路径」，所以配了**加密体检**：按前缀直接数每列还有多少明文行，
  漏了就看得见，而不是靠人盯代码。体检里还把**尚未纳入加密**的 7 个字段一并列出来，
  避免「以为已经全加密了」
- **存量数据不自动改写**：启动时悄悄改库，出问题时没人解释得清。界面上给一个「加密存量数据」，
  幂等、值不变，点了才动

最危险的一处是集群更新：原来它把「库里读出来的值」和「用户新传的值」混在同一个变量里再写回去。
加密之后这条路必须拆开 —— 库里那份是密文要先解开才能解析，新传的那份是明文解析完再加密。

验证 26 项全过，核心是「先证明明文能用 → 迁移成密文 → 再证明还能用」：
真 k3s 集群检查在 kubeconfig 变成密文后仍 healthy、也能正常列资源；主机私钥变密文后 SSH 仍在线；
重复迁移重写 0 行；只改备注 / 只改属性（密钥字段留空）之后两条链路都还能用（没把密文二次加密）。
CDP 9 项覆盖体检区块。

**没验到的**：`db_instances.secret` 这条路只过了编译与体检计数 ——
这台机器上没有可连的 MySQL / PostgreSQL 服务，所以「密文口令能真连上库」这一条本轮没有真机证据。


## 已落地：对外系统凭据全部纳入加密（含 SMTP 口令），体检清单补全

上一轮只覆盖「登录到主机 / 集群 / 库」那几列，对外系统的密钥还都躺在库里。这一轮把它们全收进来，
覆盖面从 5 列到 16 列：LDAP 服务账号口令、IM AppSecret、云账号 AK/SK、Jenkins Token、
模型上游 Key、通知渠道签名密钥与鉴权头、指标 / 日志 / 链路三个数据源的请求头、SMTP 口令。

几件比「多加密几列」更值得记下来的事：

- **上一版「尚未纳入」清单自己是错的**。补字段时发现 4 处从未被登记过：`notify_channels.header_value`、
  `log_sources.header_value`、`trace_sources.header_value`，以及 `sys_configs` 里 `key='smtp.password'`
  那一行。**清单漏登记比字段没加密更危险** —— 体检页会显得一切正常。所以体检项加了一个 `Where` 维度，
  好让「一张表里混着密钥与普通配置」这种形态（sys_configs）也能按行纳入，而不是把平台名称一起加密掉
- **顺手修掉一处真实泄露**：配置列表接口以前把 SMTP 口令原文回传给前端，任何能打开配置页的人都能
  从响应里读到。现在密钥类配置项只回 `hasValue`，提交空串表示「不修改」，前端按密码框渲染
- **解密统一放在读取漏斗上**（`ldapTarget` / `jenkinsRequest` / `openUpstream` / `openChannel` /
  `requireMetricSource` / `requireLogSource` / `requireTraceSource` / `configSecret`）。
  这么做安全的前提是 `cryptox.Open` 对没有前缀的值原样返回 —— 多解一次不会坏，
  所以「新建后立刻探活」这种拿着刚落库密文的路径也能安全地再解一次
- **解不开一律报错并点名字段**，绝不拿空值去连。LDAP 这条尤其要紧：空口令在多数目录上是匿名 bind，
  表现成「连上了但搜不到人」，比直接失败更难查
- **刻意留了两项没动**：`users.totp_secret`（动它就动了登录路径，迁移中途出错会让所有绑过 2FA 的人
  一起登不进来，要连备用码与解绑兜底一起单独做一轮）、`alert_sources.token`（是给别人推送用的令牌，
  界面上必须能看原文复制，加密了也得解回来展示）。体检页照实标成「尚未纳入」

验证 72 项全过。这一轮的做法是**给每个外部系统起一个真的服务端，并且让它真的校验凭据**：
Jenkins 侧比对 Basic Auth、模型上游比对 `Bearer`、三个数据源比对请求头、钉钉机器人**重算 HMAC 验签**、
SMTP 走真实 `AUTH PLAIN`、企业微信按真协议用 corpsecret 换 token 再读部门。
LDAP 更进一步：在 WSL 里跑了一个**真的 slapd**（非 root、1389 端口、mdb 后端、灌了一条 inetOrgPerson），
所以「密文服务账号口令能真的 bind 上目录并搜到人」是真机证据，错口令那次 slapd 回的是 `invalid credentials`。
每条链路都按「落库即密文 → 对端认这个值 → 留空改其它字段后仍然认 → 换成错值对端会拒」四步走，
第四步是为了证明不是「对端谁都认」造成的假通过。迁移路径也验了：把 4 列改回明文 → 体检数出 4 行 →
明文照旧可用 → 迁移重写 4 行 → 对端仍然认 → 再迁移重写 0 行；`platform.name` 没被 sys_configs 的迁移误伤。
UI 15 项覆盖体检卡片的新增行与配置页的口令字段（密码框、不回填、占位文案说明留空语义）。

**没验到的**：云账号 AK/SK 在平台里**没有任何消费方**（只登记不调用云 API），所以它只有
「落库即密文 + 反复留空编辑不会被二次包裹」这两条证据，没有「密文能真的调通云接口」这种证明。
IM 那条用的是本地按企业微信协议实现的服务端，不是真的 qyapi.weixin.qq.com；
Jenkins / Prometheus / Loki / Jaeger / SMTP 同理 —— 它们真在校验凭据、也真在网络上，但不是那几个真产品。


## 已落地：换密钥 / 取消加密（加密不再是单向路）

之前 `OPS_SECRET_KEY` 是一条**单向路**：设过之后既不能换、也不能退回明文，改一下环境变量就等于
把库里所有凭据作废。文档只能写「设好就不要再改」—— 那是把一个功能缺口说成了纪律要求。
这一轮补上 `POST /api/v1/secrets/rekey`，两种模式：换成另一把密钥、或者**解回明文**。

几个决定：

- **「不加密存储」是被支持的选择，不是缺省的失败态**。内网自用、不想额外保管一把密钥的部署，
  留空 `OPS_SECRET_KEY` 就行；体检卡片把当前状态写成「不加密存储」并说清代价，
  但不用安全顾虑去堵它（也不再把明文行当成必须消灭的告警）
- **先备份，备份失败就不动数据**。值不变，但这是唯一能把人从「新旧密钥各一半」里救回来的东西
- **解不开的行原样留着并计为失败**。把它覆盖成空值，会让「密钥填错」变成「凭据被清空」的
  不可逆事故 —— 单测专门盯这一条（拿另一把密钥造一行，断言它原封不动、且提示里点明有行解不开）
- **进程内的密钥热切换**（`cryptox.Box` 的密钥改放 `atomic.Pointer`）。否则「库里换完了、进程还拿着旧的」
  这段时间里所有凭据都用不了，只能靠人立刻重启去补 —— 那是半截功能。并发读写有单测覆盖
- **改不了环境变量这件事要说出来**：接口返回里明确要求把 `OPS_SECRET_KEY` 同步改成新值（或删掉），
  不改就重启会用回旧设置。启动时若发现「库里有密文但进程没密钥」，日志直接点出来、给出修复路径，
  而不是等有人点「连接主机」时才报单条记录的错

验证 29 项，按四个阶段跑，每次重启都换一种环境变量，验的就是「重启之后还认不认」：
1. 带原密钥 → `mode=plain` 解回明文：12 行密文全部重写、备份文件生成、**不重启**就能连主机与集群
2. **不带 `OPS_SECRET_KEY` 重启** → 主机仍在线、两个 k3s 集群仍 healthy、体检标注「不加密存储」
   —— 这一条就是「允许不加密存储」的真机证据
3. `mode=encrypt` 换成 `demo`：16 行明文全部加密，**不重启**主机与集群照常可用（热切换生效）
4. 带 `OPS_SECRET_KEY=demo` 重启 → 一切正常、体检 plainTotal=0
UI 7 项覆盖对话框（备份提示、环境变量提示、不加密选项、缺确认词时被挡住）。
单测新增 3 组 cryptox（运行时换密钥 / 切明文 / 并发）+ 4 组 rekey 接口（换密钥、解回明文、
跳过解不开的行、入参校验）。

**这台机器当前的状态**：`OPS_SECRET_KEY=demo`，16 列凭据全为密文。`demo` 是演示用的短密钥，
生产上要换成 32 字节以上随机串 —— 换的方式就是上面这个功能。




这一页本来很容易做成一个误导人的页面，因为「已分配」和「实际用量」是两件事：
调度器看 requests，OOM 看实际用量。只给其中一个、或把两者混在一栏里，
都会让人得出错误结论（「用量才 20%，为什么调度不上去」）。所以两个都给、分栏摆。

几条口径写在页面上，因为它们决定了数字对不对：

- **已结束（Succeeded / Failed）的 Pod 不计入**：它们还在 API 里，但资源早就还回去了
- **init 容器按「单个最大值」与普通容器之和取较大者**，与调度器规则一致。这条算错会让
  统计值偏大、让人以为节点比实际更满 —— 真集群验证时正好能对账：k8s 的 ResourceQuota
  自己就是按这个规则算 used 的，拿它当标准答案，平台算出的 1100m / 576Mi 与集群完全一致
- **占比分母用 allocatable 而不是总容量**：调度看的是可分配量（k3s 这台机器 8Gi 容量、
  7Gi 可分配，分母选错就能差出一截）
- **没配 limits 的 Pod 单独计数**：它们能把节点吃满，是容量事故的常见来源
- **命名空间筛选只影响命名空间表**，节点账本始终是全集群的 ——
  按命名空间过滤过的「节点已分配量」是个会让人做出错误判断的数字
- **metrics-server 不在时「实际用量」显示「未知」而不是 0**，并说明原因。
  本轮验证用的 k3s 恰好没装 metrics-server，所以真集群跑的是降级路径；
  metrics 可用时的分支由单测覆盖（mock 掉 metrics API，断言用量与已分配各算各的）

验证：单测 8 组（CPU/内存量的两套后缀、格式化、调度规则、已结束 Pod、配额占比按资源类型、
两种 metrics 状态下的汇总），真集群 28 项断言全过，CDP 15 项全过。
CDP 还抓到一个真 bug：没有配额的命名空间后端返回 `null`，前端一次 `map` 就把整张配额表打空了
（现在后端给空切片、前端也兜一层）。


## 已落地：Pod 结构化详情与按容器看日志

上一轮的资源详情只有 YAML，排查「这个容器为什么挂」还得自己在 spec 与 status 之间来回找。
这一轮把 Pod 单独做成结构化视图（`internal/k8s/pod.go` 的 `DescribePod`，纯函数、不发请求）。

两个决定：

- **只算不编**：字段取不到就留空，界面显示「—」。QoS 直接取 `status.qosClass` 而不是自己按
  requests/limits 推算 —— 推算规则很容易实现得和集群不一致，那种「看起来对」的字段最难排查
- **把最难找的那条摆到前面**：CrashLoopBackOff 时当前状态只会说「在等下一次重启」，
  真正的原因（OOMKilled、退出码 137）在 `lastState.terminated` 里，因此容器行里专门有一列
  「上次退出」。另外 requests/limits/探针没配时显示「未配」而不是留白 ——
  没配 limits 决定了 QoS 与被驱逐的顺序，这是事实不是缺省

另外补了两处下钻的连贯性：spec 里有但 status 里还没有的容器照样出现在列表里
（否则「少了一个容器」会变成新的疑问）；从工作负载的「关联 Pod」能直接点进 Pod 详情，
不用退回列表重选类型。

验证：`DescribePod` 单测 6 组（含 CrashLoop + OOMKilled、init 容器、缺 status 的容器、
五种卷来源、空对象不崩），真集群 29 项断言全过（k3s 的 coredns：探针、卷来源、归属 ReplicaSet、
QoS、日志按容器取、容器名写错要报错、行数越界 400），CDP 16 项全过。
