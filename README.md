# OpsOne

一体化运维管理平台。把主机资产、远程执行、堡垒机审计、容器、监控告警、组织权限收敛到一个工作台，面向中小规模自建环境。

后端 Go + Gin + GORM，前端 Vue 3 + TypeScript + Vite + Element Plus，默认 SQLite 落地、零外部依赖即可跑起来。

## 已实现


- **主机资产**：CRUD、环境/标签/状态过滤、SSH 连通性探测并采集系统信息
- **数据库与固定资产**：数据库实例纳管（按类型给默认端口；MySQL/PG 的连通性检查会**真的建连接**并回写版本号，其余类型退化为 TCP 端口探测）；固定资产台账（SN/型号/位置/使用人、关联主机、采购与保修、到保提醒与原值合计）
- **盘点与采购**：盘点批次对资产做快照后逐条登记（正常/缺失/位置变更），完成时未盘按缺失处理；采购单带明细与自动汇总，收货可按明细生成固定资产
- **云账号台账**：云厂商 AK 集中登记（列表页脱敏展示）
- **云资源同步**：阿里云账号可**真的把云上资源拉回来** —— ECS `DescribeInstances` 与云解析 `DescribeDomains`，签名与请求只用标准库实现（不引任何云厂商 SDK），**整个客户端里没有一个写操作**，平台拿着 AK/SK 也只能读。同步结果落 `cloud_resources` 表并按私网 / 公网 IP 自动匹配到已纳管主机；云上已经查不到的资源标成「已消失」保留而不是删掉（什么时候消失的是对账要用的线索）。**漂移对照**分三类：云上有平台未纳管、平台有云上没有、最近消失的；其中第二类**只在成功同步过 ECS 之后才统计** —— 没同步过就把全部主机列成「云上没有」全是噪音。未匹配的 ECS 可一键「纳管为主机」，但**登录凭据必须人来填**（云 API 拿不到主机口令，不填就是在资产表里放一条连不上的假数据）。默认**不自动同步**（`OPS_CLOUD_SYNC_SPEC` 留空），因为这一项会真的出网。**不做**：DNS 记录增删改、域名的**注册**到期时间（云解析接口给不出，需要域名注册 API）、云账单；腾讯云 / 华为云 / AWS 只登记不同步，各家签名方式不同要逐家接

- **域名管理**：台账（注册商 / 注册与到期日 / 自动续费 / 责任人 / 用途）+ **真实 DNS 解析核对** + 注册到期提醒 + 按证书 SAN 自动关联已有证书。核对是真去查一次 A/AAAA、CNAME、NS（`internal/dnsx`，仅标准库，带超时、三类并发、可指定 DNS 服务器），再和你登记的**期望值**对照。几条刻意的规矩：期望值**留空表示不核对那一类**，三类都不填时状态是「未设期望」而不是「通过」——「没检查」和「检查通过」不该是同一个颜色；只有 NS、没有 A 是很多域名的正常形态（没做网站、只发邮件），不判异常；**注册到期日只能人工登记**，为空时显示「待补到期日」并且不发提醒，不拿「空」当「还很久」。解析漂移与注册到期**分开告警**（前者是解析被改了、后者是忘续费了），走的是证书巡检那条既有告警链（固定指纹只累加不刷屏、恢复后自动 resolved、能外发到群/邮件）。云解析同步回来的托管域名可一键导入台账，但只带域名本身。**不做**：DNS 记录的增删改、WHOIS 查询、自动续费、域名注册到期日的自动获取（云解析接口给不出）

- **标签字典**：统一词表 + 分类配色 + 用量统计，主机与数据库表单里可选可新建

- **跳板机代理**：主机可关联跳板机，连接时先登录跳板机再在其隧道内握手到目标，终端与批量执行共用该链路，最多 3 层、成环即拒
- **堡垒机**：菜单里「运维执行 → 堡垒机」这一组就是通常说的堡垒机能力——Web 终端、会话审计（含录像回放与跨会话命令检索）、文件管理三件事合起来。侧边栏支持三级展开，顶栏还有一个菜单搜索（Ctrl+K），功能多了之后按名字直接跳
- **Web 终端**：SSH PTY、窗口自适应、断线提示

- **会话录像与回放**：asciinema v2 格式落盘，网页端 xterm 回放，支持 1/2/4/8 倍速与按命令定位
- **会话审计检索**：会话列表按操作人 / 登录账号 / 主机 / 状态 / 风险 / 时间范围筛；另有一条**跨所有会话的命令检索**，回答「谁在哪台机器上敲过 `rm -rf`」——按命令关键字、风险（正常 / 高风险 / 已拦截）、操作人、登录账号、主机、时间范围组合查，结果直接带上是哪次会话、哪台机器、命中哪条规则，点一行就跳到那次会话的录像并定位到该命令的时间点，也可按当前条件导出 CSV（UTF-8 BOM，单次最多 10000 条）。命中规则的描述在记录命令时**快照**下来，之后规则改名或删掉，历史记录里写的仍是当时那条。风险筛选不只看会话上的拦截计数（会话异常中断时那个计数可能停在 0），同时看命令明细里的证据
- **命令审计与拦截**：服务端在输入流上还原命令行并按正则规则判定，命中拦截规则则不下发、清空当前行并告知操作人；内置 7 条高危规则，支持在线试跑
- **下发闸门**：批量执行、脚本下发、定时任务（含调度触发）四条路径都过同一道**服务端**闸门——命令按命令规则逐行匹配，命中拦截级规则一律不下发；目标含生产主机时必须显式确认，否则后端直接拒（不是只靠前端弹窗，直接调接口也绕不过）。定时任务的拦截级命令在**保存时**就拦掉，不用等到凌晨触发才失败；调度触发用的是保存任务时那次确认。被拦下来的下发不产生执行记录，所以单独进「下发拦截流水」：命令原文、命中规则、目标与生产台数、操作人、来源 IP 都在里面。下发前可以先「预检」，结果与真正下发用的是同一套判定

- **文件管理**：SFTP 目录浏览、上传、下载、新建目录、重命名、删除，全部动作留痕
- **定时任务**：cron 表达式编排批量命令、多主机并发下发、启停与立即执行、运行历史
- **主机批量导入导出**：CSV 模板下载 → 试运行看逐行报告（行号 + 新建/更新/跳过 + 原因）→ 正式导入；按 `address + port` 判定同一台机器，重复导入是幂等更新，secret 留空保持原凭据；导出**不含登录凭据**，只有台账字段
- **脚本库**：把常用运维命令收拢成可复用资产——分类、说明、`${PARAM}` 参数化（必填/默认值）、单机超时、风险等级；保存与下发前都用「命令规则」做静态预检，命中拦截级规则的脚本一律不允许下发，命中提醒级只提示；下发走批量执行同一条链路（同样的数据权限、并发上限、生产二次确认），并记录使用次数与最近使用人
- **批量执行**：并发下发（默认上限 10）、单机超时、生产环境二次确认、逐台输出留存
- **构建发布**：登记 Jenkins 服务器并测试连通性，按 job 路径参数化触发构建；构建号与结果需手动同步（平台不轮询，也不代管构建脚本）
- **数据库查询**：不再为了查一行数据去堡垒机上敲 `mysql -u`——直接拿「数据库资产」里登记的实例浏览库/表/字段/索引（带注释、行数估算、视图区分），并跑**只读 SQL**。三层防线：语句白名单（只放 SELECT/WITH/SHOW/EXPLAIN/DESCRIBE，拒多语句、拒注释绕过、拒 `INTO OUTFILE`/`FOR UPDATE`/`pg_read_file`/`COPY ... TO PROGRAM`/`sleep()` 这类花招）+ **会话级只读**（PG 用 `default_transaction_read_only`，MySQL 连上就 `SET SESSION TRANSACTION READ ONLY`）+ 你自己在库上给的只读授权。默认 500 行截断并明确标出「还有更多」，30 秒语句超时，结果可导出 CSV（UTF-8 BOM，上限 10000 行）；执行前可以先「预检」看会不会被拦。每一次执行——成功、被拦、报错、导出——都带语句原文、操作人、来源 IP、耗时、行数进「查询流水」，留存天数可配。**只做只读查询**：不支持写操作、结果集编辑、Redis/Mongo、BI 报表
- **告警接入**：按接入源签发独立推送地址，外部监控系统 POST JSON 即可；按「标题 + 标签」生成指纹去重，同指纹重复上报只累加次数
- **告警处理**：概览卡片、级别/状态/关键字筛选、确认与恢复、每条告警的通知投递流水
- **事件中心**：把一条或多条告警升格为「要有人跟进的事」——可从告警多选建单，也可在聚合预览里把整个桶建成一个事件；支持指派（给负责人发站内消息）、处置时间线、状态流转，标记已解决时可联动恢复关联告警；详情页给出诊断上下文（按告警标签反查主机/拨测/证书/规则的当前状态，对不上的标签原样列出）。平台不自动建单
- **事件复盘**：事件解决后自动建草稿、里程碑建议值、证据自动汇聚、改进项跟踪与逾期催办、Markdown 导出
- **处置剧本**：告警/事件详情里按标签与关键词自动推荐剧本并给出匹配理由（标签 +3 / 关键词 +2 / 级别 +1，标签条件要求全部命中）；步骤里的命令过命令规则静态预检，命中拦截规则的剧本不允许启用，命令规则改了可以一键重新预检并自动停用失效剧本；带命令的步骤能一键带到批量执行页预填（只预填，预检与生产确认仍由人点）；每次使用要留结果（解决了 / 部分有效 / 没用），用过但从不解决问题的剧本会被标出来；用过的剧本不许删只能停用；复盘可以一键整理成剧本草稿（实例级标签会被剔除，止血过程按行拆成步骤，需要人改成「下次怎么做」）。内置 5 本剧本（磁盘、CPU/负载、拨测失败、证书到期、告警没人收到），进程启动时会用本地命令规则给它们补一次预检。**不做**：剧本自动执行（把判断权交给脚本比让人照着做更危险）、外部 wiki 同步
- **主机服务**：纳管机器上的 systemd unit 并登记期望态（该不该在跑、该不该开机自启、是不是关键服务），巡检现读真机状态对照，不一致就产告警（该跑没跑 / 该停在跑 / 该自启没自启 / unit 不存在）；监听端口按 /proc/<pid>/cgroup 反查归属，master/worker 模型也能归对，归不到任何 service 的端口单列出来（手工起的进程、脱管容器）；启停走 RunOnHosts 下发闸门（命令规则 + 生产二次确认 + 拦截留痕），关键服务的停止/重启/取消自启还要把 unit 名抄一遍；每次启停记「动之前是什么样、动之后是什么样」；改期望态会立刻重判漂移而不重连机器。**不做**：非 systemd 的 init 系统、容器内进程（归容器平台）、服务安装与卸载（归发布）
- **配置文件**：登记「哪台机器的哪个路径该是什么内容」，基线从真机抓（不让人从零写，从零写的基线第一次下发就会把机器打坏）；巡检 SFTP 现读算 sha256 对比基线，不一致产告警并给出 diff 行数与统一 diff；平台上可编辑新版本（只存版本不碰机器，先看 diff 再决定下发）；下发顺序不可调换：现读真机 → 存成回滚点 → 写临时文件 → 备份 .bak + chmod --reference 保权限 + mv 原子替换 → 回读校验 hash → 可选 reload 关联服务；任一版本可回滚，回滚默认把该版设为新基线；sudo 由远端按「目标文件是否可写」自行判断。**不做**：模板渲染与变量替换（那是发布系统的活）、目录级管理、二进制文件
- **事件 SLA**：在「监控告警 → 监控设置」里按事件级别（紧急 / 警告 / 提示）分别定「多久要有人接手」（响应 SLA）与「多久要恢复」（恢复 SLA），默认响应 15 / 60 / 480 分钟、恢复 60 / 240 / 1440 分钟，另有临期提前量（默认 5 分钟）与重复提醒间隔（默认 4 小时），目标填 0 表示这一级不设 SLA；这 8 个配置项也出现在「系统配置」的 monitor 分组里（同一批行，两个入口）。口径写在页面上，因为它决定数字算不算数：**响应 SLA 从建单时间起算**——平台不知道故障真正开始于几点（那是复盘里人填的），只承诺「从平台上有这张单开始算」；**指派不算响应**，只认状态离开「待处理」（接手 / 直接解决 / 判定关闭）或写下第一条处置记录，否则值班的人靠互相转单就能把响应 SLA 刷成全绿；恢复 SLA 从建单算到「已解决」，判定无需处理而「已关闭」的事件不计 SLA。事件列表有 SLA 列（响应 / 恢复两个 tag 带实时倒计时）、「已超时 / 临期」筛选与两个快筛 chips，事件详情多两行，事件统计给出 slaBreached / slaRisk；筛选是翻成 SQL 在分页之前执行的，不是查出来再过滤。临期与超时由 `OPS_SLA_SPEC`（默认每 2 分钟）扫未完结事件并给负责人发站内消息（没有负责人退回建单人），两条 SLA 各自独立提醒、各自记上次提醒时间，重复提醒间隔内不再发；找不到可提醒的人时仍在事件时间线留痕并说明原因。**SLA 不落库**，每次输出按当前时间重新算，前端拿后端给的绝对「到点时间」自己走倒计时，页面不刷新也准。列表筛选与统计**只算「还没做到且已超时 / 临期」的单子**，历史上超时但已经做完的不在这里记账（那是复盘看耗时的口径）。**不做**：按业务线 / 服务 / 标签分别设目标、把提醒走通知渠道（邮件 / IM / Webhook）、「历史上超时但已完成」的筛选口径




- **聚合策略**：把同类告警按 接入源/级别/标题/任意标签 维度实时归桶，配合成桶阈值看清"哪一类在刷"；支持归桶预览与策略重叠检测。可选开启「抑制通知」——同一个桶在窗口内只通知首条，其余告警仍然入库、页面可见，并在告警上记录是哪条策略抑制的
- **静默与维护窗口**：发布或维护期间**只拦外发通知，不拦入库**——窗口内的告警照常出现在告警列表并标记「已静默」，事后能回答「为什么没收到通知」。条件按 级别 / 来源 / 标题关键字 / 标签 组合（填了的都要命中），保存前可以试算「这套条件现在会拦掉哪些告警」；不填条件必须显式勾选「匹配全部告警」，避免手滑全局静音。窗口到点自动失效不用手工解除，也支持提前结束；**值班升级按当下时间重新判定**，窗口里不叫人、窗口一过立刻恢复。已经拦过告警的窗口不允许删除（否则那些告警查不到原因），只能提前结束或停用
- **拨测探测**：HTTP（状态码 + 响应体关键字）与 TCP 拨测，连续失败达到设定次数才告警、恢复即关闭；记录每次结果并算可用率，历史保留天数由「数据留存」统一控制。所有拨测共用一个节奏（`OPS_PROBE_SPEC`，默认每 5 分钟）
- **容器平台**：粘贴 kubeconfig 纳管集群，调用 Kubernetes API（手写 REST，不引入 client-go）；集群列表给出版本、节点就绪数与最近检查结果，不可达或有节点 NotReady 自动写告警并走通知路由、恢复即关闭（`OPS_KUBE_CHECK_SPEC`，默认每 5 分钟）。工作负载页按命名空间看 Deployment / StatefulSet / DaemonSet 的副本就绪情况、Pod 状态与容器异常原因、以及集群事件（可只看 Warning）。只接受内嵌凭据的 kubeconfig
- **容器日志**：在 Pod 列表上直接看容器日志——多容器可切换（含 init 容器）、行数可选 200/500/2000/5000、可带时间戳、可看「上一个容器」的日志（排查 CrashLoopBackOff 就靠它）、可每 5 秒自动刷新、可下载成文件。单次最多取 1MB，超了如实标注「只显示前面部分」而不是静默截断。**不做 follow 流式跟随**（一次取一段，少一条长连接），也**不提供容器内执行命令（exec）**
- **容量与配额**：回答「还能不能再塞」，而且把最容易被混淆的两个数**分开摆**——**已分配**（活着的 Pod 的 requests 之和）决定调度器还愿不愿意往这台机器放 Pod，**实际用量**（要 metrics-server）决定会不会 OOM。节点表给容量 / 可分配 / 已分配 / limits / 实际用量与各自占比（占比分母用 `allocatable` 而不是总容量，因为调度看的是可分配量）；命名空间表给 requests / limits / 实际用量，并单独标出**没配 limits 的 Pod 数**（这些 Pod 能把节点吃满）；另有 ResourceQuota 的已用 / 上限与占比。三条口径写在页面上：已结束（Succeeded / Failed）的 Pod 不计入（资源早还回去了）；init 容器按「单个最大值」与普通容器之和取较大者，与调度器规则一致；**集群没装 metrics-server 时「实际用量」列显示「未知」而不是 0**，并说明原因。命名空间筛选只影响命名空间表，节点账本始终是全集群的（按命名空间过滤过的节点已分配量会让人做出错误判断）
- **Pod 详情与日志**：Pod 点开是**结构化概况**而不是一段 YAML —— 容器逐个列出镜像、当前状态与原因、**上一次退出的原因与退出码**（CrashLoopBackOff 时当前状态只会说"在等下一次重启"，真正的 OOMKilled / 退出码 137 在 `lastState` 里）、重启次数、requests/limits 与探针是否配了（没配就写"未配"，因为它决定 QoS 与被驱逐的顺序）、端口与挂载点；另有 Pod 条件、卷及其来源（ConfigMap / Secret / PVC 只给名字不碰内容）、归属控制器、QoS（直接取 API Server 算好的 `status.qosClass`，平台不自己推算）。**字段取不到就留空，不给默认值**。日志页签按容器选（含 init 容器，启动失败时它们的日志才是关键），可选最近 100/200/1000/5000 行、带时间戳、看重启前那一份；"上一次的日志"在容器没重启过时集群会拒，平台如实报错而不是回一份空日志。从工作负载的「关联 Pod」可以直接点进某个 Pod，不用回列表重选类型：看单个对象的 YAML（自动去掉 status 与 resourceVersion / uid / managedFields 这类集群自己维护的字段，改完可直接提交），走 Kubernetes **服务端 apply** 落盘，提交前可「预检」让 API Server 完整校验（含准入控制）但不落盘；Deployment / StatefulSet 还能直接改副本数，Deployment / StatefulSet / DaemonSet 支持**滚动重启**（与 `kubectl rollout restart` 同一做法：给 Pod 模板打时间戳注解让控制器换掉 Pod，界面上明说这不是原地重启容器）。字段被 kubectl 或别的控制器管着时会明确报冲突，确认后可勾「强制接管」。资源浏览覆盖 **17 种类型**，按工作负载 / 网络 / 配置 / 存储 / 集群分组，支持名称过滤与分页；对象详情除了 YAML 还有**它自己的事件**（按 `involvedObject` 反查，不用在整命名空间的事件里翻）和**关联 Pod**（按 spec.selector 的等值标签查，与集群自己的选法一致；用 matchExpressions 选不出来时如实说明，不按名字前缀猜）。三档权限界线摆在界面上：可写（Deployment / StatefulSet / DaemonSet / CronJob / Job / Service / Ingress / ConfigMap / PVC）、**只读**（Pod / ReplicaSet / Endpoints / Namespace / Node / PV / StorageClass —— 由控制器维护，改了也会被改回去，因此不给编辑入口）、**脱敏只读**（Secret 只给键名不给值，那份 YAML 也禁止提交，否则会把真实值覆盖成占位符）。**不提供删除、不开放 RBAC**——要动这些仍然走 kubectl。写操作单独要 `kube:write` 权限，每次改动（apply / scale / restart，含预检与失败）都留痕，记下对象、提交内容、API Server 的原话与操作人，保留天数纳入「数据留存」
- **Helm 应用（只读）**：release 直接从集群里 `type=helm.sh/release.v1` 的 Secret 解出来（两层 base64 + gzip + JSON），**不需要 helm 二进制、也不访问 chart 仓库**。给出 release 名、命名空间、状态、chart 与应用版本、第几次发布、一共留了几个历史版本、最近一次操作说明与对应的 Secret 名。同名 release 只显示最新 revision。**不做** install / upgrade / rollback / uninstall —— 那需要真正的 Helm 引擎（模板渲染、钩子、依赖、CRD 处理），半套实现比没有更危险；也**不返回 values 与渲染后的 manifest**（values 里常有数据库口令，manifest 动辄几百 KB）。只认 Helm 3 默认的 secret driver，用 configmap driver 存 release 的集群在这里看不到
- **自定义资源（CRD，只读）**：CRD 清单是**运行时从集群里读出来的**，不是平台内置白名单 —— 装了什么就能看到什么。给出组、kind、作用域、served 与 storage 版本（**分开显示**，混在一起会让人查错版本）、短名；认得的常见组（Gateway API / cert-manager / Prometheus Operator / Argo / Istio / Flux / Calico…）额外给一句中文说明，认不出的照样能浏览。点进去按 storage 版本列实例，可切到其它 served 版本（查未在服务的版本会被拦下并列出可选项，而不是拼出一个 404 的路径）；详情**保留 status** —— 自定义资源的 status 往往才是要看的那部分（Argo 的同步状态、cert-manager 的签发结果）。CRD 自己没就绪（`Established≠True`）时**在查实例之前就拦下并说清原因**，不让人看到一个莫名的 404。单个类型一次最多 500 个实例，超出如实标注。**不提供编辑**：平台不懂自定义资源的语义，改错一条 Gateway 或 Application 的代价太大
- **Gateway API 路由（只读）**：把 HTTPRoute 的三层嵌套拍平成「什么流量 → 送到哪」——`parentRefs` / `hostnames` / `rules[].matches[]` → `backendRefs[]` 在 YAML 里得来回翻。几个照实说明的地方：没有 `matches` 的规则按 Gateway API 的默认语义显式写成「所有请求」，没有后端的规则写成「不会把流量送到任何地方」，`path` 没写 `type` 时补成默认的 `PathPrefix`，跨命名空间的后端标出「需 ReferenceGrant」（平台只提示、不代为核对）。集群**没装 Gateway API 时明说没装**并指路去看 Ingress，不给一张空表。只解析 HTTPRoute，其它 Gateway 对象在「自定义资源」页看原文
- **RBAC 账户（只读）**：回答「这个 ServiceAccount 实际能干什么」—— 从 RoleBinding / ClusterRoleBinding 反查到 Role / ClusterRole 再读 rules，**k8s 里没有这样一个现成对象**。即使只看某个命名空间，Role 与 Binding 也**一律全集群读**：命名空间里的 SA 可能被 ClusterRoleBinding 授权，只读本命名空间会漏掉最危险的那一类。绑了 `cluster-admin`、拿到通配符（`*`）权限、没有任何授权、**孤儿绑定**（绑了但引用的 Role 不存在 —— 表现是「绑了却什么权限都没有」，很容易被当成权限不够去加更大的角色）都单独标出来并可筛选，危险的排在最前。只反查 ServiceAccount：User / Group 主体由集群外的认证系统管，平台里没有对应对象。**不提供编辑** —— 改 RBAC 就是改提权路径
- **节点与命名空间（只读）**：只看它们**自身**的健康与约束 —— 资源账本（已分配 / limits / 实际用量）仍然只在「容量与配额」页算一遍，两处各算迟早会对不上，而对不上的数字比没有数字更糟。节点侧：Ready 与各压力条件（`DiskPressure` / `MemoryPressure` / `PIDPressure` / `NetworkUnavailable` —— 注意判断方向是反的：Ready 该为 True，这几个该为 False）、污点及其效果说明（`NoSchedule` 不调度新 Pod / `NoExecute` 连已有的都赶走）、cordon 状态、容量与可分配**分开给**（调度看 allocatable，差值是预留给系统组件的）、节点上活着的 Pod 数与上限（已结束的不计入）、**kubelet 版本偏斜**单独提示（升级做到一半停下来是很常见的现场）。排序按严重程度而不是问题条数 —— 一台 NotReady 比一台有三条轻微提示的更该先看。命名空间侧：Pod 分布（运行/等待/失败）、ResourceQuota 已用/上限（只列 hard 里设了上限的项，`status.used` 里那堆零值是噪音）、有没有 LimitRange、**卡在 Terminating 时把 finalizer 一起列出来**（命名空间删不掉几乎总是因为它）。一条口径：「既没有 ResourceQuota 也没有 LimitRange」**只在真的读到了配额对象之后才判定** —— 没权限看配额和没配配额是两件事。Pod 数读不到时显示「未知」而不是 0。**不提供** cordon / uncordon / drain / 打污点、也不提供命名空间的创建与删除
- **集群服务转发**：把集群里的 Pod / Service 端口临时映射到平台上的一个端口，相当于把 `kubectl port-forward` 挪到平台来跑，不用给每个人发 kubeconfig。走 **API Server 的 WebSocket 通道**（不引 client-go、不自己实现 SPDY），每条进来的本地连接单独拨一条 WebSocket。转发 Service 时**每条连接重新解析后端 Pod**，Pod 重建或扩缩容之后隧道还能继续用（已验证）。隧道是进程内的活物，重启即消失，启动时会把残留记录标成「已关闭」而不是假装还活着；页面上实时给出活跃/累计连接数、双向流量、剩余时长与拨号失败原因。约束都由部署时的环境变量定死并在页面上写明：监听地址、端口区间、隧道条数、单条并发连接数、存活时长（到点自动关）。**隧道端口本身不做认证**，能连到它的人等同于能访问被转发的服务，详见 docs/SECURITY.md 第 16 节
- **平台健康**：一页看平台自己的状态——运行时长/协程/内存、调度器注册情况与内置巡检的最近运行、通知渠道与兜底路由是否可用、24h 投递失败、规则评估异常、告警积压、主机探测覆盖、数据库与录像目录占用；每项给出 正常/需关注/异常 与判定理由
- **业务拓扑**：把一条业务链路画成图，节点绑定平台里已有的主机 / 数据库 / 拨测 / 证书（或标为「外部依赖」），颜色直接由被绑资源的当前状态换算，并写明判定理由（「主机离线」「拨测连续失败 3 次」「证书剩 12 天」）；SVG 画布可拖动排布、布局批量保存，连线做了校验（禁自环、禁重复、两端必须同属一张拓扑），依赖成环给出闭合路径提示但不阻止。拓扑自己不采集数据、不产生告警
- **主机指标**：走已有的 SSH 通道采集 CPU / 内存 / 磁盘 / 负载 / 进程数 / 连接数 / 运行时长，**不装 agent、不依赖 Prometheus**；远端只跑一条只读命令（读 `/proc` 与 `df`），百分比换算都在平台侧做。磁盘只统计真实块设备并排除 snap 的 squashfs 与只读镜像挂载，否则「100% 占用」会天天误报。采集失败也落库并单独告警，超过 30 分钟没采到的样本标为过期且不参与告警判定。默认每 5 分钟采集（`OPS_HOST_METRIC_SPEC` 可改或关闭），列表带趋势图，保留天数纳入「数据留存」
- **链路追踪**：接入已有的 Jaeger，按服务/操作/最小耗时/时间范围搜 trace，列表直接给出入口服务与操作、总耗时、span 数、涉及的服务、**出错 span 数**；点进去是 span 瀑布图（按父子关系深度优先排列、相对偏移与耗时按整条链路跨度换算），点某个 span 看它的全部标签。日志里看到 trace_id 可以直接粘进去查。出错判定同时认 OpenTracing 的 `error=true`、HTTP 5xx 与 OTel 的 `otel.status_code=ERROR`。**平台不接收上报、不存链路数据**，也不做服务依赖拓扑图（Jaeger 自己有）
- **日志查询**：接入已有的 Loki，在平台里写 LogQL 查日志行——标签下拉可直接拼出选择器（`{app="web"}`）、时间范围与条数可选（最多 5000 条）、支持最新在前/最旧在前、单行过长自动截断并标记、可下载为文件。跨流结果会按时间归并成一条时间线（Loki 只保证每个流内有序），并显示 Loki 扫了多少行/多少字节。支持多租户（`X-Scope-OrgID`）与鉴权头。**平台不存日志、不改写 LogQL**：报错原样来自 Loki（它的报错常是纯文本，也照实带出）；聚合类表达式返回的是指标，会明确提示去「指标查询」页。**不做实时 tail**
- **安全响应（研判台的另外三块）**：**原始流水视图** —— 事件的证据摘要截断到 2000 字，点「看原始流水」按 `RefTable`/`RefID` 取回**没被截断的原文**（完整命令行、会话里的操作人与目标主机、审计请求路径）；原始行被数据留存清理删掉时如实说明而不是留一片空白，会话父表没了也明说「查不到是谁敲的」。**升格为事件工单** —— 平台没有对接任何外部工单/SOAR，做一个「派发记录」只会是永远空着的表，所以「派发」的诚实落法是交给事件中心那套**已经在跑**的机制：负责人、处置时间线、SLA 计时与超时提醒，升格出的工单自动带 SLA（响应口径仍是「指派不算响应」），同时把安全事件从待研判推进到研判中并留痕，重复升格被拒。**学习建议** —— 从已有数据算出该改哪个配置，**通过就真的去改**：反复被报的未登记端口并进暴露面基线（只动基线一列）、判了忽略却还在累加命中的指纹加进误报白名单、观察态但已多次 warn 的特征提到拦截态（连命令规则一起重写为 block，这是唯一有真实拦截后果的一类，单独二次确认）。建议**每次现算不落库**（存下来就会过期），只持久化「拒绝」（可撤销，否则那个按钮点了等于没点），应用时重算、不信前端传来的内容，复现少于 3 次的不进建议。**安全概览** —— 只聚合已有数据，最该读的是「做不出真数据的部分」那一段：阻断包数/流量、进程与连接、登录失败爆破、读接口越权、外部威胁情报这五项没有采集，所以一个数字都不给 —— 用 0 冒充「没有问题」是最容易骗人的看板。**不做处置审批**：内网自用、管理员自己对自己负责，加一层点「同意」不会让处置更安全，只会让人绕过它
- **主机日志（不依赖任何日志系统）**：直接 SSH 在主机上跑 `tail` / `grep` / `du` 读文件 —— 没部署 Loki 的环境里这是唯一能看到日志的路径（上面那条「日志查询」没有 Loki 就是个空页）。三件事：**实时查看**（末尾 N 行 / grep 关键字，单次最多 1MB、在远端就截断）、**关键字巡检**（按 **inode + 字节偏移**增量读，只看上次之后的新增内容；文件轮转或被清空时水位自动归零；**首次巡检只记水位、不回溯历史** —— 一个跑了半年的日志里成千上万条 ERROR 不是刚出的问题）、**日志目录占用**（总占用 + 最大的几个文件，采全部主机而不只是配了监控点的那些）。关键字是**固定字符串、不区分大小写**，不是正则 —— 让人在界面上填正则迟早有一条灾难性回溯把巡检卡死；先判忽略词再判关键字。「读不到文件」也会告警：一个本该一直在写的日志突然消失，等于这个监控点已经瞎了，静默失败比没有监控更糟。**全模块只跑只读命令**，也**不把日志内容搬进库**（只记命中行数与第一行样本）。路径必须落在 `OPS_LOG_PATH_PREFIXES`（默认 `/var/log`）下 —— 这是唯一真正的安全边界。**不做**：实时 tail -f 流、日志入库与全文检索、正则关键字、改动主机上的任何东西
- **指标查询**：接入已有的 Prometheus（或兼容实现），在平台里直接跑 PromQL——即时查询看当前值（表格），范围查询看趋势（折线图，步长按时间范围自动算、点数上限 11000 与 Prometheus 对齐）。支持多数据源与默认源、连通性检查（读 buildinfo 与 tsdb 状态，顺带显示版本与序列数）、指标名补全、常用查询收藏。**平台不存时序数据、不改写 PromQL**：语法报错原样来自 Prometheus（带 errorType 与列号），返回的警告也照实透出；曲线超过 60 条会截断并提示把查询收窄
- **暴露面监测**：登记每台对外机器「该开哪些端口」，平台从自己所在网络位置定时做 TCP 连接核对——开着但没登记的端口写告警并走通知路由，登记齐全后自动恢复；首次纳管可一键把当前开放端口「登记为基线」。也会记「登记了却没开」（服务可能挂了）但不为此告警。端口清单支持 `22,80,443,8000-8010` 混写，单目标一次最多 1024 个端口；只做连接探测，**不发探针载荷、不识别服务指纹、不做全端口扫描**。默认每天 04:20 扫一次（`OPS_EXPOSURE_SPEC` 可改或关闭），每次扫描落一条历史，保留天数纳入「数据留存」
- **模型资源池**：把多个供应商的模型收在平台后面做成一个网关——调用方只认平台给的 Alias，平台按权重挑一条上游转发（`POST /api/v1/ai/chat/completions`，参数与 OpenAI 的 chat 接口一致），失败自动换下一条，换供应商或加降级备份都不用动调用方代码。每次调用（含失败与自动切换）都落一条流水，token 取上游返回的 usage，成本按每个上游登记的单价（元/千 token）算。「检查」不只拉 `/models`，还会真打一次 `max_tokens=1` 的最小调用——**有些实现的 `/models` 不校验密钥**（llama.cpp server 实测如此），只探列表会得出「可用」的假结论。**只支持 OpenAI 兼容的非流式 chat**（流式拿不到完整 usage，用量就成了估算）；**提示词与回复正文一律不落库**（那是业务数据）；**成本是按登记单价算的估值，不等于供应商账单**，平台不做对账
- **用量与成本**：把网关的调用流水按时间、模型、上游、调用人切开——快捷区间（今天按小时 / 近 7 天 / 近 30 天 / 自定义）、调用次数与成本的趋势图（没人调用的那天补成 0 而不是把折线直接连过去）、三张排名表（按 Alias / 上游 / 调用人，按成本从高到低），以及可按当前条件导出的流水 CSV（UTF-8 BOM，单次最多 10000 条，只有元数据、没有正文）。平均耗时只算成功调用（失败的多是连接失败的 0，混进去会把均值拉垮）。分桶在服务端用 Go 做而不是写 SQL 的日期函数，避免时区把跨天的账算串。流水的保留天数纳入「数据留存」（默认 365 天，删了那段时间的账就算不出来了）
- **Agent（只读分析器）**：把平台自己的数据喂给模型换一段结论——上下文可取「最近未恢复告警（可按级别）/ 某台主机最近的采样 / 某个执行作业的逐台结果（失败的排前面）/ 某次会话敲过的命令（带风险与命中规则）」，提示词用 `text/template` 写（`{{.context}}` 放数据、`{{.input}}` 放运行时补充），保存时就校验模板语法、Alias 是否真有可用上游、以及「取了数据却没在模板里用 context」这种一定跑不出效果的配置。**它只读、不执行任何命令、不改任何东西**，结论仅供人参考。每次运行记一条：喂了多少条/多少字符（撞上限会标「已截断」）、模型结论正文、token、成本、耗时；上下文取不到（主机不存在、作业没结果）时**先落一条失败记录再报错，且不会去调模型**。Agent 的调用与网关共用同一条派发路径，因此一并计入「用量与成本」（来源标 `agent`）。运行记录的保留天数同样纳入「数据留存」
- **告警规则**：基于平台自身数据的规则引擎（主机 CPU/内存/磁盘/单核负载最高值与采集失败、主机探测离线/失联、证书到期与巡检失败、批量执行与定时任务失败、构建失败、告警积压、通知投递失败），支持比较符 + 阈值 + 统计窗口 + 连续命中次数降噪；默认每 5 分钟评估（`OPS_ALERT_RULE_SPEC` 可改或关闭），命中写告警并走通知路由，条件不再满足自动恢复，规则可「试跑」立即评估
- **告警规则版本与回滚**：每次改动留一份配置快照，差异做**字段级**并说人话（「阈值 80 → 200」「级别 warning → critical」，比较符翻中文、布尔翻启用/停用），可一键回滚到任一版。**刻意不做策略审批** —— 审计日志不记请求体，所以在此之前「谁把阈值从 80 改成 200」查不出来；而改错一条告警规则的后果是**静默的**（监控看着在跑、实际已经不报了，之后几周没人知道），真正兜住这件事的是留痕 + 回滚，不是事前点一次「同意」。细节：快照**只含配置态**（`HitStreak`/`LastValue`/`LastStatus` 那几个每轮评估都在变，混进来会让定时评估每 5 分钟产生一个新版本）；内容与上一版相同时不产生新版本；版本功能上线前就存在的规则，第一次改动会先把「改之前的样子」补成第一版；**删除也留一版**，误删可以恢复成一条**新规则**（新 ID，**默认停用** —— 直接让它开始评估等于在没人确认的情况下恢复了一条可能已不适用的策略）；回滚本身也记一版，中间那几版不会消失
- **跨渠道通知模板**：IM 文本与 webhook JSON 也能配模板了（之前只有邮件能）。更要紧的是**把变量表收口到一处** —— 改之前真实发信变量、预览样例、界面提示各写一遍，对得上是人工维护的巧合，前端也拿不到权威清单；现在只有一份代码里的定义，真实发信、样例、界面清单、模板校验全部从它派生。**模板是可选的覆盖，不是前置条件**：没配、配了但停用、类型对不上、渲染失败，四种情况一律回落到原来的硬编码格式 —— 一条告警发不出去比格式不好看严重得多；webhook 渲染结果不是合法 JSON 时回落并**把原因写进投递流水**，否则使用者只会发现「模板像是没起作用」却查不到原因。变量白名单**在保存时就校验**：`text/template` 对缺失的变量会静默渲染成空串，不校验要到真发信时才表现成「正文里少了一段」。顺带修掉一个真缺口：**值班呼叫邮件**此前和普通告警一模一样、收件人看不出这是在叫自己 —— 现在有专门的 `oncall.call` 模板与值班场景变量（值班表 / 第几级 / 派给谁）
- **值班大屏**：一屏投出去给值班看。与「告警态势」分工明确 —— 那一页是**运营统计**（按天按源的分布，复盘用），这一页是**当下**（现在有什么没人管、哪条快超时）。30 秒自动刷新、一键全屏、纯 CSS 柱状图（不为一条趋势线引图表库）。两处刻意的设计：**「被抑制」的告警必须显示** —— 它们仍然在响、只是没外发，不显示的话「告警数为 0」会被读成「一切正常」；**通知投递失败数放进大屏** —— 告警发不出去是最隐蔽的一种故障，平台看着在告警、实际没人收到。SLA 超时/临期的单子最多列 8 条（超时最久的在前），趋势只留 24 小时 —— 大屏上塞二十个数字等于没有大屏
- **IM 组织同步**：用企业自建应用的凭据（与「通知渠道」里的群机器人是两套东西）把企业微信 / 钉钉 / 飞书的部门树与成员同步进平台——部门按 `provider:部门ID` 记在部门 Code 上、挂到指定公司下；成员先按绑定关系找人，找不到再按同名账号建立绑定，都没有才新建（随机口令 + 只在新建时给默认角色）。同步遵循**只补不毁**：部门只新建与改名、**从不删除**；用户**从不删除**，IM 侧查不到的人改为停用（可关，内置 admin 永不停用）；**已有用户的角色与口令一律不动**，否则手工调过的权限会被下一次同步抹平。预演与执行走同一段逻辑，预演**一行都不写库**、并同样留一条记录。三家的错误都藏在 HTTP 200 里（企微/钉钉是 `errcode`、飞书是 `code`），适配器一律先看错误码再看状态码。接口地址可覆盖（走私有代理或对着假上游验证）。**这些接口的路径与字段名来自公开文档，没有在真实企业租户上验过**（见 docs/SECURITY.md 23）
- **IM 扫码登录**：同步进来的人可以直接用企业微信 / 钉钉 / 飞书扫码进平台，不用再记一套口令。按应用单独开关，登录页只列开了开关的入口；点进去跳各家授权页，回调时用 code 换 IM 身份（企微 `getuserinfo` 拿 userid；钉钉换到的是 unionId，要再用 `/topapi/user/getbyunionid` 反查成 userid 才对得上通讯录；飞书用 open_id），再按绑定表找平台账号。**必须先绑定才放进来**：IM 里有、平台没绑过的人一律拒（不自动建号——那等于把「谁能进平台」的决定权交给通讯录），账号停用的也拒。回调**不把 JWT 放进 URL**，只带一个一次性 ticket（2 分钟内有效、用过即废），前端拿 ticket 再换令牌，换的时候重新查一遍账号状态；发起时的 `state` 同样一次性（5 分钟），回调重放会被拒。ticket / state 存在内存里，**重启会让进行中的扫码失效，多实例部署必须换成共享存储**（见 docs/SECURITY.md 24）
- **检测规则**：判定「多条告警的组合」——并发窗（同一窗口内都出现）、顺序链（必须按先后发生）、窗口 Join（还要落在同一个对象上，比如同一台主机）；每步按标题/摘要关键字 + 接入源 + 级别 + 标签匹配告警，窗口内**发生过**的告警都算（含已恢复的），命中写告警并走通知路由、条件不再满足自动恢复。默认每 5 分钟评估（`OPS_DETECTION_SPEC` 可改或关闭），建规则时可「预演」看每步各命中哪些告警。检测不吃自己的输出，避免规则被自身告警顶住不恢复
- **告警值班与升级**：排班表按小时/天/周在成员之间轮换（交接时刻由基准时间的时分决定），可按级别只接管一部分告警；代班在时间段内顶替当班人。告警「firing 且未确认」超过设定分钟数就升一级，最多升到设定级数，每一级叫对应位次的人——站内消息一定发，勾了「发邮件」再按用户邮箱补发一封，每次叫人都落一条升级记录（没填邮箱就记 `failed` 而不是静默跳过）。同一告警同一级只叫一次；只扫最近 24 小时且不早于排班表创建时间的告警，避免新建表就把历史积压全叫一遍。默认每分钟扫描（`OPS_ONCALL_SPEC` 可改或关闭），可「试跑」立即扫一遍并看结果。**不支持短信/电话**（账号体系里没有手机号），也不做换班审批
- **通知路由与渠道**：按优先级 + 级别 + 标签匹配选路，支持兜底路由与选路预演；渠道分 webhook（HTTP POST 固定 JSON，可带鉴权头）、**群机器人**（企业微信 / 钉钉 / 飞书，按各家报文发纯文本，支持 @ 成员与 @所有人，钉钉加签与飞书签名校验都做了）、email（SMTP + 邮件模板）与 silent（只留记录）。群机器人**不看 HTTP 状态码定成败**：被移出群、超频、签名过期都会返回 200 加一个非零 errcode，平台按 errcode 判定并把厂商原话写进投递记录
- **双因子口令**：平台账号可绑定标准 TOTP（SHA1/6 位/30 秒，任意验证器），登录时口令 + 动态验证码两步校验，同一验证码在有效期内不可重复使用；策略可设为强制，未绑定账号除个人页与绑定接口外一律被后端拒绝；解绑需口令 + 验证码，忘带手机由管理员重置（无恢复码）
- **LDAP / AD 账号接入**：用公司域账号口令登录平台，不用再维护一套口令。登记目录服务器（明文 / LDAPS / StartTLS，内网自签证书可显式跳过校验）后可**测试连接**（真建连、真用服务账号 bind、真在 Base DN 下数人）、**搜索目录里的人**并绑定到平台账号，还有一个**试登录诊断**：用真实口令走一遍，把「过滤器没命中 / 目录拒绝口令 / 目录认了但平台没账号 / 没绑定 / 开关是关的」逐步列出来——登录页那句「用户名或密码错误」查不出这些。两条硬规则：**绑定即托管**，账号一旦绑定，本地口令立即失效（否则域账号停用后平台里那份旧口令就是后门）；**绝不按目录自动建号**，目录里有、平台没有的人一律拒（与 IM 扫码登录同一原则）。可选「首登自动绑定」：平台已有同名账号时首次用域口令登录即绑定，账号不存在仍然拒绝。域账号同样要过双因子；平台只读目录，不写回、不做组织同步、**不做组到角色映射**（那等于把「谁是管理员」交给目录管理员）
- **API 令牌（服务账号）**：给 CI、脚本、外部系统一条正经的调用凭据，不用把某个人的账号口令写进流水线配置。令牌明文**只在创建与轮换时出现一次**（库里只存 SHA-256，丢了只能轮换）；**默认只读**（只放 GET），要写必须显式关掉只读并授予权限码；令牌权限 = 授予的权限码 **∩ 归属人当下的权限**，归属人被降权或停用，令牌立即跟着失效；可设来源 IP 白名单（支持 CIDR）、有效期、随时撤销或轮换（旧明文立刻作废）。令牌**不能用于 Web 终端与端口转发**（只认请求头、拒绝 WebSocket 升级——那条链路必须是人，会话审计才有意义），也**不受强制双因子约束**（它不是人，约束在只读 / 交集 / 可撤销上）。每次写操作在审计里同时记下令牌名与归属人，被 403 拒掉的调用一样留痕；`GET /api/v1/me/whoami` 让调用方自己确认「我是谁、生效权限有哪些、是不是只读」
- **凭证库（共享登录凭据）**：一份口令 / 私钥存一处，多台主机引用它；**轮换一次，所有引用主机的下一次连接自动用新密钥**，不用逐台改、也不会改漏。密钥**永不出接口**（连脱敏版都不给），界面上只展示公钥指纹、存储方式、责任人、最近轮换与最近一次成功登录。配了 `OPS_SECRET_KEY` 时口令与私钥以 **AES-GCM 密文**落库，没配就是明文，**页面顶部如实写明是哪种**（不做"有凭证库就等于加密了"的暗示）；已有明文凭据轮换一次才会转成密文。几条硬规则：私钥在**落库前**就解析一次并算指纹，解析不了的不落库；**带口令的私钥现在可用**（平台此前完全不支持，加密私钥直接报错），"缺口令"与"口令不对"分开报；主机切到共享凭据时**清空本机那份口令**（留着就是不会被轮换的后门），从共享凭据切回本机自填必须同时给新密钥；凭据被禁用 / 删除 / 解不开密时，引用它的主机**连不上并点名是哪份凭据**，绝不静默回退到旧口令；还有主机在引用的凭据**拒绝删除**。可以先"测试连接"再绑定：用目标主机的地址与跳板链、认证强制用被测凭据，真连一次并回报实际登录到了谁。**不做**：口令借用审批、到期自动轮换、SSH CA 短期证书；数据库 / 云账号 / Jenkins / 模型上游那些密钥仍各自存在自己模块里
- **账号密码库 + 2FA 验证码库**：凭证库管的是「平台拿去登主机」的密钥，这两页管的是「人自己要用」的账号——某个后台系统的管理员口令、某个第三方平台的登录账号。安全模型正好相反：明文**必须能取出来**，否则这一页只是份不能用的清单；既然能取，「不返回密钥」那条防线就不存在了，改成**取用必留痕**——取口令 / 出验证码 / 导出种子都记下谁、何时、从哪个 IP、填了什么理由，而且**留痕写库失败时接口直接报错、明文不发出去**（留痕是前置步骤，不是收尾步骤，有测试守着）。权限分两档：`vault:manage` 维护条目、`vault:reveal` 取明文，看得见清单不等于能取。**改口令只能走「轮换」**，编辑接口显式拒绝携带口令——否则「最近轮换时间」就是假的，逾期提醒跟着失真；设了周期的口令逾期进告警通道（逾期超过一个完整周期升为 critical），**没设周期的不参与**（平台不知道你的口令该多久换一次，替你假设一个 90 天只是制造噪音）。2FA 验证码库解决「账号开了两步验证、验证器绑在离职同事手机上」：种子托管在平台，谁需要谁现算一个码。这是**一次明确的降级**——种子存进来，这些账号的 2FA 就退化成「能进这一页的人都能登」，页面第一段就写着这句话。验证码用**服务器时间**算，时钟偏差超过 30 秒算出来的码全是错的、表现却是「验证码总是不对」，所以出码时一并显示服务器时间；录入时用 base32 解一遍，乱码当场拒绝，otpauth 地址里带了 8 位 / 60 秒 / SHA256 / HOTP 这类非默认参数也直接拒绝而**不静默忽略**（忽略的话码永远对不上，没人想得到原因在这）。导出 otpauth 地址等于交出第二因子原件，与取明文同级留痕。条目删除后留痕不删（存了取用当时的名字），有种子关联的账号条目拒绝删除。两列新密钥都登记进了加密体检清单。**不做**：审批后才能取（内网自用，审批只会让人把口令抄到本地记事本）、浏览器自动填充、复制即焚（明文已经到浏览器了，清剪贴板不构成保护）、与目标系统联动改密、口令强度检查
- **发件邮箱（自定义邮箱）**：在这之前全平台只有一套 SMTP（系统配置里 `smtp.*` 六个键），所有邮件都从同一个地址发。现在发件账号是一张表，解析顺序是**渠道指定 → 默认邮箱 → 全局 SMTP**；一个都没登记时仍走全局配置，所以升级后邮件照发，想搬过来有「从系统配置导入」（**口令一起带过来**，让人对着看不见的旧口令重输是最容易错的一步）。**渠道指定的邮箱被删或停用时，那个渠道的邮件直接失败并点名原因**，不静默换发件人——静默换的结果不是「发不出去」而是「发出去了但署名不对」，后者更难发现。这一轮还修了一处真问题：**STARTTLS 之前是被动发生的**，老实现 `smtp.tls=false` 时交给标准库，而标准库的行为是「对方声明支持就升级，不声明就发明文」，于是中继一改配置，SMTP 口令和告警正文就以明文出网、而界面上看不出任何区别；现在加密方式是显式三选一（SSL 直连 / STARTTLS / 不加密），选了 STARTTLS 而对方不支持就报错。另外新增了跳过证书校验（内网自签的 SMTP 之前根本连不上，但这是降级，界面上会标出来）、中文主题按 RFC 2047 编码（之前部分客户端乱码）、发件人显示名。试发是真发一封，失败也返回 `ok:false` 而不是 500
- **代理检测（出口代理）**：**检测 = 直连一次 + 走代理一次**，两个结果摆在一起——只测代理的话，「网络本来就不通」和「代理坏了」返回的是同一个报错，人会按错的方向排查；四种组合各给一句能照着做的结论（如「代理不可用，但直连是通的：问题在代理本身，不在网络」）。**HTTP 拨测可以指定走某个代理**，这是目前唯一真的用到代理的地方，其它出网点（云 API、IM、Webhook、指标 / 日志 / 链路数据源、邮件）都还是直连，这一点写在页面上，不让「登记了代理」被读成「平台出网都走代理了」。**代理不可用时那条拨测直接失败并点名原因，绝不退回直连**——退回直连会让「出口代理挂了」表现成「目标一切正常」，监控是绿的但监控的路径已经变了。TCP 拨测不接代理（HTTP 代理只能代理 HTTP(S)，用 CONNECT 测任意端口测到的是代理的放行策略）。支持 http / https / socks5（标准库 `Transport.Proxy` 原生支持，不引依赖）；**测试地址默认留空**，替你预设一个公网回显服务等于替你决定了这台机器可以访问公网，出口 IP 读不到时照实说读不到
- **防火墙策略**：SSH 直连真机读规则，不装 agent。自动识别 firewalld / ufw / 裸 iptables 三种后端，**只认真正在跑的那个**——装了 ufw 却没 `enable` 的机器判为 iptables 并明说「ufw 的配置不影响当前包过滤」；裸 iptables 会标出「规则重启即失效」。命中计数从 `iptables -nvL` 取真数字，取不到的规则显示「无计数」而不是 0（这两件事不能混）。平台侧只登记「期望有哪些规则 + 责任人 + 生命周期 / 到期时间」，与真机现读结果对账成 **已生效 / 待下发 / 真机多出来** 三种状态；真机上有而平台没登记的存量规则**平台绝不擅自删**，只能「接管登记」后由人决定。下发前先**预检**：把将要执行的命令原样摊开，并走与批量执行同一个下发闸门（命令规则拦截 + 生产主机二次确认）；下发后**自动回读核对**，验不上就明说「执行了但没生效」。每次下发与回滚前后各存一份真机规则原文，可回滚到任意一份（回滚同样过闸门）。另有安全组（一组规则铺到一批成员主机，只登记、仍需逐台下发；删组只删组里的规则模板，已铺到主机的副本解绑保留，不会连带清空各机登记）与清理建议（过期 / 全网段放行 / 没责任人 / 长期零命中 / 与真机不一致）。**明确不做**：实时流量监控、进程连接、带宽限速、Agent 接入审批——这些要常驻 agent，纯 SSH 只能定时采样，做出来是假的实时。防火墙命令需要 root：主机账号不是 root 时自动加 `sudo -n`（开关见系统配置 `firewall.sudo`），需要为该账号配好免密 sudo





- **安全意识（培训与考核）**：必修内容 + 已读签署 + 小测验判分。发布会真的给范围内（全员 / 角色 / 部门含子部门）每个启用账号建待办并投一条站内消息；**正确答案绝不下发到浏览器**，判分只在后端做（否则「考核」就是把答案先发过去再问一遍）；确认已读记的是人、时间与来源 IP，是一条签署记录；到期未完成的人会被再提醒一次（`OPS_AWARENESS_SPEC` 默认每天 09:00，同一项一天只提醒一次）并在完成明细里被点名。有签署记录的项目不允许删除、已发布的不允许改必修范围（记录会对不上人）。**不做**：课件上传与在线播放、证书与学分、「没做完就禁止登录」那种强制（把提醒问题变成可用性事故）
- **特征库**：危险命令与端口特征的共享来源，规矩是**特征必须能落到一个真在跑的检测点上**，不收只能看的模式表。command 类「应用」后会在命令规则里生成 / 维护一条规则 —— 那张表是下发闸门（批量执行 / 脚本 / 定时任务 / 防火墙下发）与 Web 终端真正在用的，所以「已应用」等于「真会拦」；**灰度**就落在这里：observe 映射成 warn（只提醒）、enforce 映射成 block（直接拦下）。命令规则可能被人手工改过或删掉，所以每行都给对账状态（已生效 / 被改过 / 规则没了）并能一键按特征重写。port 类特征不改暴露面基线（「哪些端口允许开」是人的决定），只拿真机 TCP 探测出来的开放端口核对，还会指出哪些命中端口不在该目标基线里。内置 12 条特征，其中 7 条直接挂在内置命令规则上（一打开就是「已生效」的真实状态）。**不做**：病毒特征与文件哈希比对（要常驻 agent 扫盘）、特征自动更新源
- **安全事件（研判台）**：把平台已经在产生的安全类流水汇聚成可研判的「安全事件」，四个来源都是只追加的流水表——下发闸门拦下的高危命令（`exec-guard`，**只取 `action=block`**；`status=blocked` 还包含「目标含生产主机要二次确认」这种流程拦截，那是工作流保护不是安全事件，混进来会把研判台变成噪音场）、Web 终端里被拦下的命令（`terminal`）、真机 TCP 探测到的未登记开放端口（`exposure`，一个端口一条）、越权被拒的写操作（`authz`，403）。界面上**不提供手工新建事件**。事件带源地址 / 目标 / 协议 / 证据摘要 / 命中次数，指纹只认「谁 / 从哪 / 对谁 / 干了什么」（不含时间与原始流水 ID，不去重的研判台第二天就没人看了）；支持批量研判（平台**第一个真正的后端批量接口**，单次上限 200，此前的「批量」都是前端循环调单条）、处置留痕（只追加链路：collect / status / note / respond / rehit）、误报白名单、一键生成封禁规则草稿。几条硬规矩：判为「误报 / 忽略 / 已处置」这三种让线索从值班视野里消失的状态**必须写结论**（后端强校验）；判误报会把指纹加入白名单让采集器跳过，但**挡掉的次数照记**并按次数倒序排（挡得异常多通常说明当初判错了），撤销白名单会把事件拉回待研判并写明期间挡掉了多少次；**结案之后又命中**单独计一列，采集器不改人判过的状态，但会写一条 rehit 留痕、列表能一键筛出、排序默认顶到最前（「结案了还在响」要么判错了要么攻击还在继续，不能被「已处置」盖掉）。采集游标按**原始流水的自增 ID** 推进（不用时间戳水位，四张表都是只追加 + 自增主键，按 ID 推进不会因时钟回拨或同一秒多行而漏采重采），单来源单次最多消费 500 行。**特征库 port 类特征第一次有了持久化的消费方**：未登记开放端口命中启用中的 port 特征时按特征级别提升事件级别，并把命中的特征名写进证据。「封禁源地址」只生成**防火墙规则草稿**（待下发 / 临时 / 7 天到期 / drop / 入向），**刻意不下发** —— 下发要走防火墙自己的 `firewall:apply` 与下发闸门；研判台如果能直接改真机规则，一个误判就能把自己的运维通道封掉。封禁必须带端口（底层三家防火墙共有的表达要求 tcp 规则带端口，做不出「封这个地址的所有端口」），ssh 类事件默认 22，推不出来就报错要求明确填、不替人猜。默认每 5 分钟采集一次（`OPS_SECEVENT_SPEC`），采集**只读本地库、不连主机、不执行任何命令**。**刻意没有的来源**：登录失败爆破——审计中间件只挂在鉴权后的路由组上、登录接口在公开路由上，所以平台**从来没有记录过一次失败登录**，这是诚实的空白，界面上不假装覆盖；同理审计跳过 GET，读接口的越权尝试也查不到。**不做**：删除事件（让噪音消失的正规路径是「忽略」或「误报 + 白名单」）、封禁草稿自动下发与自动解封（临时规则 7 天到期是唯一的自动收口）、多级审批、派发给外部系统
- **证书管理**：登记域名/端口后探测对端 TLS 证书，记录颁发者、SAN、有效期、SHA256 指纹与根证书链校验结果；到期阈值可按证书设置，命中「即将到期 / 已过期 / 巡检失败」自动写入告警并走通知路由，换证后自动恢复。默认每天 08:00 巡检（`OPS_CERT_CHECK_SPEC` 可改或关闭），不签发、不托管私钥、不做自动续签
- **菜单管理**：内置菜单可改标题/图标/排序/隐藏（不被启动覆盖），自建菜单可完全自定义
- **站点导航与邮件模板**：内部系统入口卡片墙；邮件模板用 Go template 语法，带语法校验与样例预览

- **告警态势**：24h/7d/30d 趋势折线、级别与来源分布、Top 标签、平均确认与恢复时长
- **公告与站内消息**：公告草稿/发布/下线，发布即向全员投递站内消息（下线撤回未读）；严重告警自动推送给持有处理权限的用户，顶栏铃铛显示未读角标

- **RBAC**：用户 / 角色 / 菜单三级授权，菜单与按钮两级权限，后端逐接口校验
- **组织与数据权限**：公司 + 多级部门树；角色级数据范围（全部 / 本部门 / 本部门及下级 / 仅本人 / 指定部门），多角色取并集，作用于主机列表、探测、终端、文件管理、批量执行与定时任务，配有生效诊断
- **资源授权**：数据范围之外按用户/角色把指定主机或数据库额外授予，可限定动作（终端 / 文件 / 执行 / 管理）与有效期；与菜单权限是 AND 关系，两层都过才放行


- **操作审计**：写操作记录操作人、接口、路由模板、状态码、来源 IP、耗时；按操作人 / 方法 / 接口关键字 / 成功失败 / 来源 IP / 时间范围组合检索，关键字同时匹配实际路径与路由模板（搜 `/hosts/3` 就是这台主机身上发生过的事），结果里直接给出失败条数可一键只看失败；按当前检索条件导出 CSV（UTF-8 BOM，单次最多 10000 条）
- **个人工作台**：待办汇总、我的资源（按数据范围过滤的主机统计与分布）、我的操作流水 / 会话 / 执行记录
- **平台配置**：分组键值配置，带类型校验；平台名称与登录提示支持白标（改配置即生效，无需改代码），批量执行并发、上传上限、录像保留天数均由配置驱动
- **数据留存**：执行记录、拨测记录、通知投递、操作审计、会话流水、已恢复告警六类数据各自配置保留天数（0 表示永久），先「试算」看每类会删多少行、哪些是连带删除（逐台执行结果、命令明细与录像文件）、哪些删后无法追溯，确认无误再执行；默认每天 03:30 自动清理（`OPS_RETENTION_SPEC` 可改或关闭），清理动作写审计，平台健康页同步展示可清理行数




其余模块（容器平台、监控告警、安全合规、配置中心等）菜单与权限位已就位，实现状态见 [docs/ROADMAP.md](docs/ROADMAP.md)。

## 快速开始

需要 Go 1.25+、Node 20+、pnpm。

```bash
# 后端，默认监听 :8080，首次启动自动建表并创建 admin
cd server
export OPS_JWT_SECRET="$(openssl rand -hex 32)"
go run ./cmd/server

# 前端，默认 http://127.0.0.1:5173
cd web
pnpm install
pnpm dev
```

初始账号 `admin`，初始口令取自 `OPS_ADMIN_PASSWORD`（默认 `Admin@123456`），**首次登录后立即修改**。

Windows PowerShell 下设置环境变量用 `$env:OPS_JWT_SECRET="..."`。

## 部署

生产部署看 **[docs/DEPLOY.md](docs/DEPLOY.md)**（二进制 + systemd / Docker Compose、反代与 TLS、备份恢复、升级、排障）。要点：

- `make dist` 打出一个包：静态二进制 + 前端产物 + 部署样例。配上 `OPS_WEB_DIR` 后**后端直接托管前端**，单进程就能交付，不需要另配 nginx
- `OPS_ENV=prod` 下**不安全的配置会让进程拒绝启动**（默认 JWT 密钥、默认 admin 口令、空/含 localhost 的 CORS 白名单、开着的 DEBUG），而不是打一行 warn 就放行
- 探活分两个：`/healthz` 只看进程，`/readyz` 真查数据库（负载均衡与容器探针该用后者）
- SIGTERM 会走**优雅退出**：停调度 → 通知并断开 Web 终端 → 关闭转发隧道并落库 → 等在跑的请求收尾 → 收尾会话状态
- 自带**备份与恢复**：`ops backup` / `ops restore`（SQLite `VACUUM INTO` 快照 + 录像 tar.gz），默认每天 03:00 自动备份并早于数据留存清理
- 交付物：`Dockerfile`、`docker-compose.yml`、`deploy/opsone.service`、`deploy/nginx.conf.example`、`deploy/opsone.env.example`、`Makefile`

## 配置项

全部通过环境变量注入：

- `OPS_ENV` — 运行模式 `dev`（默认）或 `prod`；prod 下安全底线不达标直接拒绝启动，见 docs/DEPLOY.md 第 5 节
- `OPS_ADDR` — 监听地址，默认 `:8080`
- `OPS_DSN` — SQLite 文件路径，默认 `ops.db`；换 MySQL/PostgreSQL 需要改 `server/internal/db/db.go` 的 driver 并处理方言差异（**不是改个配置就行**）
- `OPS_WEB_DIR` — 前端构建产物目录，配了就由后端托管前端并做 SPA 回落；留空则只有 API
- `OPS_JWT_SECRET` — 令牌签名密钥，**生产必填**（≥32 字节）；dev 下未设置会用开发默认值并告警
- `OPS_TOKEN_TTL_HOUR` — 令牌有效期，默认 12
- `OPS_ALLOW_ORIGINS` — CORS 与 WebSocket Origin 白名单，逗号分隔，默认 `http://localhost:5173`
- `OPS_TRUSTED_PROXIES` — 可信反代的 IP/CIDR，逗号分隔。**默认为空即谁都不信**，`X-Forwarded-For` 一律忽略（否则审计里的来源 IP 可被伪造）；部署在 nginx 后要填 nginx 地址
- `OPS_ADMIN_PASSWORD` — 内置管理员初始口令，默认 `Admin@123456`
- `OPS_RECORD_DIR` — 会话录像目录，默认 `recordings`
- `OPS_SHUTDOWN_TIMEOUT_SEC` — 优雅退出等待上限，默认 30；批量执行是同步请求，给小了会把作业截断
- `OPS_SSH_STRICT_HOST_KEY` — 是否校验 SSH 主机指纹，默认 `false`；置 `true` 后首次连接记录指纹（TOFU），之后指纹变化即拒绝
- `OPS_SECRET_KEY` — 凭据字段的加密密钥（任意长度口令，内部派生 256 位），覆盖凭证库、主机凭据、kubeconfig、数据库口令与各类对外系统密钥（含 SMTP 口令）。**默认值是演示密钥 `demo`**，所以默认就是加密的、带演示数据的库文件开箱可用；`demo` 写在仓库里等于公开，**prod 模式下带着它启动会被直接拒绝**。要明文落库（被支持的选择）设 `OPS_SECRET_KEY=off`（也接受 none / plain / disabled），界面会标成「不加密存储」。换密钥或退回明文走「凭证库 → 密钥加密体检 → 更换密钥 / 取消加密」（先整库备份再逐行重写，并要求你把这个环境变量同步改掉），不要直接改这个变量
- `OPS_AWARENESS_SPEC` — 安全意识逾期提醒的 cron 表达式，默认 `0 9 * * *`；置空则逾期未完成的必修项不会自动催办（功能仍可用，只是靠人去翻完成率）
- `OPS_VAULT_SPEC` — 密码库口令轮换逾期检查的 cron 表达式，默认 `30 9 * * *`；置空则设了轮换周期的口令逾期也不会有人被提醒，那个周期就只是一行说明文字。只读本地库，一天一次够了；没设周期的条目本来就不参与
- `OPS_REVIEW_SPEC` — 复盘改进项逾期催办的 cron 表达式，默认 `10 9 * * *`；置空则逾期的改进项不会有人被提醒（跟踪仍可用，只是复盘写完就烂在系统里）。同一个人的多条逾期项合并成一条站内消息，同一条项目一天最多催一次
- `OPS_SERVICE_SPEC` — 主机服务巡检的 cron 表达式，默认 `*/10 * * * *`；置空则纳管服务只能手动巡检，「该跑的没跑」不会自动被发现。每次巡检会对有纳管服务的主机各开一次 SSH，节奏不宜太密
- `OPS_CONFIG_SPEC` — 配置文件巡检的 cron 表达式，默认 `*/30 * * * *`；置空则「配置被人改了」不会自动被发现（仍可手动巡检）。每个文件一次 SFTP 读取，节奏不宜太密
- `OPS_SLA_SPEC` — 事件 SLA 扫描的 cron 表达式，默认 `*/2 * * * *`；置空则响应 / 恢复超时不会有人被提醒（列表上的 SLA 列与筛选照样准，只是没人来叫）。扫描只读本地库、不连主机，比「临期提前量」更密没有意义
- `OPS_SECEVENT_SPEC` — 安全事件采集的 cron 表达式，默认 `*/5 * * * *`；置空则新的安全线索不会自动汇聚成事件（页面仍可用，只是要靠人去翻各条流水）。采集只读本地库、不连主机、不执行任何命令，单个来源单次最多消费 500 行原始流水
- `OPS_CLOUD_SYNC_SPEC` — 云资源同步的 cron 表达式，**默认留空 = 不自动同步**（与其它巡检项相反）。这一项会真的出网调阿里云 OpenAPI，默认就开等于替你决定了「这台机器可以访问公网、也愿意消耗云 API 配额」；要自动建议 `0 */6 * * *`。留空时页面上「立即同步」照样可用，只是云上新开或释放的机器要靠人点一下才会被发现
- `OPS_DOMAIN_SPEC` — 域名巡检（DNS 核对 + 注册到期）的 cron 表达式，默认 `0 8 * * *`；置空则「解析被人改了」和「域名快到期了」都只能靠人想起来去点一下
- `OPS_DNS_SERVER` — 域名核对用的 DNS 服务器（如 `223.5.5.5` 或 `8.8.8.8:53`），默认留空走系统 resolver。**内网 DNS 经常把生产域名覆写到测试地址**，用它核对出来的是内网视角、跟外部用户看到的不是一回事；想核对「外面看到的解析」就在这里指一个公共 DNS。界面上会回显每次核对实际用的是哪个，免得「为什么和我 dig 的不一样」变成查不清的问题
- `OPS_HOST_LOG_SPEC` — 主机日志巡检（关键字扫描 + 日志目录占用采集）的 cron 表达式，默认 `*/15 * * * *`；置空则日志里新冒出来的错误与「日志目录快把盘写满了」都只能手动巡检。每个监控点一次 SSH，节奏不宜太密
- `OPS_LOG_PATH_PREFIXES` — 允许读取的日志目录前缀，逗号分隔，默认 `/var/log`。**这是「主机日志」模块唯一真正的安全边界**：路径由人在界面上填，没有这道白名单，有这个页面权限的人就能读主机上任意文件（包括 `/etc/shadow` 与主机私钥）。放开新目录时想清楚这一点


- `OPS_BACKUP_SPEC` / `OPS_BACKUP_DIR` / `OPS_BACKUP_KEEP` — 自动备份的节奏、落盘目录与保留份数，默认 `0 3 * * *` / `backups` / `7`；节奏刻意早于数据留存清理
- `OPS_CERT_CHECK_SPEC` — 证书巡检的 cron 表达式（标准五段），默认 `0 8 * * *`；置空则不做定时巡检，只能在界面上手动触发
- `OPS_ALERT_RULE_SPEC` — 告警规则评估的 cron 表达式，默认 `*/5 * * * *`；置空则只能在界面上手动试跑
- `OPS_PROBE_SPEC` — 拨测执行的 cron 表达式，默认 `*/5 * * * *`；置空则只能手动拨测。所有拨测共用这一个节奏
- `OPS_RETENTION_SPEC` — 数据留存清理的 cron 表达式，默认 `30 3 * * *`；置空则只能在界面上手动试算与清理
- `OPS_DETECTION_SPEC` — 检测规则评估的 cron 表达式，默认 `*/5 * * * *`；置空则只能在界面上手动试跑
- `OPS_KUBE_CHECK_SPEC` — 容器集群连通性检查的 cron 表达式，默认 `*/5 * * * *`；置空则只能在界面上手动检查
- `OPS_HOST_METRIC_SPEC` — 主机指标采集的 cron 表达式，默认 `*/5 * * * *`；置空则只能手动采集。采集走 SSH，节奏太密会给主机和平台都加压
- `OPS_ONCALL_SPEC` — 值班升级扫描的 cron 表达式，默认 `* * * * *`；置空则只能在界面上手动试跑。扫描只读本地库，每分钟跑不算负担，但比「未确认超时分钟数」更密没有意义
- `OPS_EXPOSURE_SPEC` — 暴露面扫描的 cron 表达式，默认 `20 4 * * *`；置空则只能手动扫描。扫描会对目标发起大量 TCP 连接，别配得太密

集群服务转发（隧道端口不做认证，这几个值就是它的全部约束）：

- `OPS_FORWARD_BIND` — 隧道监听地址，默认 `0.0.0.0`；只给平台本机用就设 `127.0.0.1`
- `OPS_FORWARD_PORT_MIN` / `OPS_FORWARD_PORT_MAX` — 可占用的端口区间，默认 `30000` / `30099`
- `OPS_FORWARD_MAX` — 同时存在的隧道条数上限，默认 `8`
- `OPS_FORWARD_TTL_MINUTES` — 隧道存活时长上限（分钟），到点自动关闭，默认 `120`
- `OPS_FORWARD_CONN_MAX` — 单条隧道的并发连接上限，默认 `32`；每条连接都要向 API Server 单开一条 WebSocket


- `OPS_DEBUG` — `true` 时输出 SQL 日志并启用 gin 调试模式；`dev` 默认开、`prod` 默认关（prod 下显式打开会被拒绝启动）

数字与布尔类型的变量写错（例如 `OPS_TOKEN_TTL_HOUR=twelve`）会直接报错退出，不会静默回退默认值。

运行期参数（平台名称、登录提示、批量执行并发、上传上限、录像保留天数、双因子策略）在「系统管理 → 系统配置」里改，改完即生效，不需要重启。

## 菜单与权限

菜单树当前由种子数据统一维护（`server/internal/db/db.go` 的 `Seed`），按 ID 分段：10 工作台 / 100 资产 / 200 运维执行 / 300 容器 / 400 监控告警 / 500 安全合规 / 600 智能与成本 / 700 配置中心 / 800 系统管理 / 900 消息中心。种子数据是权威来源，启动时全量覆盖并清理不在清单内的历史菜单。

新增页面：在 `web/src/views` 下建 `xxx/index.vue`，再往种子数据里加一条菜单，`Component` 填 `/xxx/index` 即可；前端按后端下发的菜单动态注册路由。按钮级权限用 `v-perm="'host:create'"`，后端对应接口挂 `middleware.RequirePerm`。

## 安全须知

部署前务必阅读 [docs/SECURITY.md](docs/SECURITY.md)。当前有几处明确的取舍需要知晓：

- 配了 `OPS_SECRET_KEY` 时，**20 列凭据**都以 **AES-GCM 密文**落库：凭证库、主机自带凭据、容器集群 kubeconfig、数据库实例凭据，以及 LDAP 服务账号口令、IM AppSecret、云账号 AK/SK、Jenkins Token、模型上游 Key、通知渠道签名密钥与鉴权头、指标 / 日志 / 链路三个数据源的请求头、SMTP 口令、账号密码库口令与 2FA 托管种子、发件邮箱口令与出口代理口令。仍是明文的只剩 TOTP 密钥与告警推送令牌两项（原因写在 SECURITY 第 2 节），「凭证库 → 密钥加密体检」会逐列列出密文 / 明文行数。同时拿到数据库与 `OPS_SECRET_KEY` 的人依然能拿到全部凭据 —— 加密挡的是只拿到库文件或备份的那类场景。注意账号密码库与 2FA 种子两列的加密**只防库文件被拷走**，防不了「有权限的人取明文」（那是设计如此），后者靠取用留痕兜
- **不加密存储是允许的**：`OPS_SECRET_KEY=off` 即明文落库，界面会把当前状态写成「不加密存储」并说清代价。反过来，这个变量**默认是演示密钥 `demo`**，所以默认加密、但 `demo` 是公开值 —— prod 模式启动会被拒，正式部署必须换成随机串。加密开关不是单向的：体检卡片上的「更换密钥 / 取消加密」能换成另一把密钥、也能解回明文（先整库备份，再逐行解开重写，解不开的行原样留着并报出来；进程内密钥立刻切换、不用停机，但要按提示把环境变量同步改掉）
- SSH 主机指纹默认不校验，存在中间人风险，可用 `OPS_SSH_STRICT_HOST_KEY=true` 开启
- 命令拦截是 PTY 层面的启发式手段，能挡常见误操作，但拦不住 `vim :!cmd`、base64 解码执行等绕过，不能当作强制访问控制
- 会话录像包含终端输出全文，可能含配置与令牌，需按敏感数据管理
- 安全事件的证据摘要里会包含被拦下的命令原文（可能夹着口令），与会话审计同档；看得到安全事件就等于看得到那些命令。封禁只生成防火墙规则草稿，真机变更仍要走 `firewall:apply` 与下发闸门
